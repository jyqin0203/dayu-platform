# 管理员扫描任务交付

日期：2026-10-03；分支 feat/frontend-session。管理员概览和本轮扫描页面均尚未提交；本轮不触发真实扫描。

## 范围与入口

管理概览 → 扫描任务：手动扫描、刷新列表、分页历史、查看任务、刷新任务状态及错误明细。
沿用 surgical-web-fusion 的局部适配规则，仅扩展管理页扫描区域，不改观测台或产品配置。
任务状态为运行中/成功/部分成功/失败；后端未提供完成百分比，因此不画进度条。状态由用户手动刷新，不启动后台轮询。

## 输入输出

| 文件 / 函数 | 输入 | 操作与输出 |
| --- | --- | --- |
| scan-client.js / history | 一基页码 | GET admin/index-scans?page=N&pageSize=20，返回任务列表与分页信息 |
| detail | 正整数任务 ID | GET admin/index-scans/{id}，返回任务状态、数量和安全错误列表 |
| start | 无路径或目录参数 | GET Session 验证 ADMIN 和最新 CSRF，再 POST admin/index-scans，返回已接受任务 |
| admin-scans.js / mountScans | 失权回调 | 绑定扫描区交互，返回 reset/load 给管理概览调用 |
| reset / load | 概览刷新或身份变化 | 清空旧明细、使旧请求失效；身份通过后加载第一页 |

admin.html/admin.css 增加局部区域；admin.js 在身份验证后加载扫描历史，401/403 清空并隐藏整个管理数据。
依赖只有现有 Session、Operations HTTP 契约与标准 JavaScript，无新增第三方包或后端修改。

## 规则

- 手动扫描必须先确认；取消不请求 POST。
- 提交中禁用按钮，后端 409 显示已有运行任务。网络超时提示先查看历史，不自动重发可能已被接受的任务。
- 不允许浏览器指定服务器数据目录，不删除原始文件。
- 页码和任务 ID 严格验证；列表与详情分别防止迟到响应覆盖。
- 刷新/翻页清除旧任务明细；总页数缩小时回到最后有效页。
- 错误相对路径、代码、消息全部 textContent 渲染，不解析 HTML。
- 历史列表每页 20 条；错误明细展示后端返回的有界错误列表，不声称包含超出后端保存上限的全部错误。
