日期：2026-10-03。分支：`feat/frontend-data-adaptation`。本轮未提交、未写数据库、未改后端。

## 输入 → 操作 → 输出

页面选中产品 → `loadTimeline` 查询 Legacy 最新批次/帧列表 → 得到 `{cycle, all, frames}` → 页面确认仍为当前请求 → 更新时间轴和预报时效按钮。

- `cycle`：UTC 起报时间；实况为空。
- `all`：合法路径、合法时间、排序去重后的文件列表。
- `frames`：预报保留全部查询结果（包括未来有效时间）；实况沿用旧页面最近文件为锚点的 24 小时/30 分钟抽帧。
- 降水依然只有一个 PRECIP 产品，读取三个时效目录，不创建三个产品。三个目录各一张合法图片才展示；缺图或请求失败明确报错。
- 实况的显示窗口不等于后端约三天的保留窗口，也不是新增历史检索功能。本轮不改变已迁入页面的抽帧策略。

## 文件和函数

新增 `frontend/public/flat-20260925/timeline-data.js`，只依赖标准 JavaScript 和注入的 JSON 请求函数，无新依赖。

| 函数 | 输入 | 行为 / 输出 |
| --- | --- | --- |
| dateOf | 12 位 UTC 时间 | 严格验证年月日时分，返回 Date；非法日期抛错 |
| stamp | 图片路径 | 只取文件名最后一个独立 12 位时间；没有时返回 undefined，不使用目录时间兜底 |
| leadHours | 图片路径、起报时间 | 返回有效时间减起报时间的小时差，支持跨日 |
| realtimeWindow | 已按有效时间排序的合法列表 | 保留原有 24h/30min 显示帧，空输入返回空列表 |
| loadTimeline | 产品条目、JSON 请求函数、可选根目录 | 请求批次与列表，校验目录/日期/时效、排序去重；返回独立快照，错误抛给页面提示 |

修改 app.js：调用上述加载函数；仍保留 generation 检查，只有当前选择的结果可以写入页面状态，旧请求的批次不再修改共享时间轴。时间显示继续明确标记 UTC。

修改 package.json，新增 timeline-data.test.mjs：将新测试纳入 npm test，因此现有前端 CI 自动覆盖。
