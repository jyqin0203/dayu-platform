# 后端配置与图片资源接入

本轮只统一本地配置和图片访问，不扫描真实目录、不改前端、不补缺失 NC 命名规则，也不改变下载鉴权。

## 1. 数据目录

在 `.env.local` 填写真实存在的绝对路径，不加引号；留空表示暂不接入。以下只是例子：

```dotenv
DAYU_NETCDF_ROOT=E:/Dayu-dev-data/netcdf
DAYU_WEBP_ROOT=E:/Dayu-dev-data/WebP/WebP_V2_Dpi500_4KM
DAYU_COLORBAR_ROOT=E:/Dayu-dev-data/public
```

WebP 根直接包含 `realtime/`、`forecast/`，不要填某一个产品或时次目录。NC、WebP、色标分开存放，公开图片目录与 NC 根不能相同或互相包含。

| 本地配置 | 传入 Java 的配置 | 用途 |
| --- | --- | --- |
| `DAYU_NETCDF_ROOT` | `dayu.indexing.roots.netcdf-data` | NC 索引和受控下载共用根 |
| `DAYU_WEBP_ROOT` | `dayu.indexing.roots.webp-preview` | WebP 索引和图片服务共用根 |
| `DAYU_COLORBAR_ROOT` | `dayu.catalog.colorbar-root` | Catalog 发布时核验色标，以及图片服务定位色标 |

脚本只读取白名单配置，不执行文件中的代码；空路径不会变成当前工作目录。配置变化需要重启。**配置目录不等于扫描**，启动脚本仍关闭定时扫描。

## 2. 图片地址

`<DAYU_WEBP_ROOT>/realtime/CTH/example.webp` 同时对应：

- 新接口：`/media/webp/realtime/CTH/example.webp`
- 旧页面兼容：`/WebP/WebP_V2_Dpi500_4KM/realtime/CTH/example.webp`

旧地址使用与 Legacy API 相同的逻辑别名，不复制第二份文件。第一版仍是单 DPI 根，不宣称已支持任意 DPI 切换。

色标目录组织为：

```text
<DAYU_COLORBAR_ROOT>/
  CPP_Colorbar/vertical/CTH_Colorbar.webp
  colorbars/custom.png
```

对应 `/CPP_Colorbar/vertical/CTH_Colorbar.webp` 和 `/colorbars/custom.png`。产品 `colorbarPath` 填带目录的相对路径，例如 `CPP_Colorbar/vertical/CTH_Colorbar.webp`。目录应在启动前存在，新增配置目录后重启。

仅开放 WebP、色标的 WebP/PNG/JPG/JPEG；不开放 SVG、NC、配置文件或目录列表。拒绝路径穿越、隐藏路径及向根外逃逸的符号链接/junction；不把整个色标父目录注册成网站根。图片地址匿名公开，不逐张检查产品发布状态，目录只应放允许公开的图片，并由可信进程维护。NC 仍必须通过 Download 授权。

代码入口：`interfaces/media/PublicMediaConfiguration` 注册 URL；`ConfinedImageResolver` 检查真实路径和图片后缀，再交给 Spring 传输 Resource。`dayu.media.enabled` 普通 Java 启动时默认关闭，本地脚本显式开启；生产用 Nginx 托管时可关闭 Java 图片服务。

## 3. Qwen 配置

填写 `.env`（密钥不要写入 `.env.example`）：

```dotenv
DASHSCOPE_API_KEY=自行填写
DAYU_COPILOT_ENABLED=true
DAYU_COPILOT_QWEN_MODEL=qwen3.8-flash
DAYU_COPILOT_QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

`start-local.ps1` 读取这四项并传给真实 `QwenAiClient`。密钥仅经子进程环境传递，不进入命令行、生成的配置 JSON 或日志。未配置时默认关闭；启用却缺少密钥时在启动服务前报错。启动本身不调用模型，只有请求 Copilot 接口才可能产生费用。

不改文件也可以强制关闭：`scripts/start-local.ps1 -DisableCopilot`。

## 4. 生效方式

修改 Java 后先停止旧后端，再构建和启动：

```powershell
.\scripts\stop-local.ps1
.\scripts\build-local.ps1
.\scripts\start-local.ps1
```

旧脚本启动而没有进程记录时，停止脚本会拒绝盲目终止，需要先核实 PID。不要结束所有 Java 进程。

IDEA 直接启动 Java 不会自动执行 PowerShell 的 `.env` 读取逻辑，需要提供等价 Spring 属性/环境变量。本轮接通的是仓库的本地启动脚本，没有额外引入 dotenv 依赖。
