# 前后端迁移与最终验收指南

当前版本提供观测台、独立数据检索、Session账号、授权下载、管理员产品/模式/扫描/用户/审计管理及 AI 助手。不是已部署生产版本。

## 1. 新电脑启动

准备 Git、JDK17、Docker Desktop、Node.js24；启动 Docker。克隆 main 后按 [新电脑首次启动指南](新电脑首次启动指南.md) 执行：

```powershell
git clone https://github.com/jyqin0203/dayu-platform.git
cd dayu-platform
./scripts/setup-local.ps1
./scripts/build-local.ps1
./scripts/start-local.ps1 -DisableCopilot
./scripts/initialize-local-products.ps1 -BootstrapAdmin
cd frontend
npm.cmd ci --ignore-scripts
npm.cmd run check
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

setup 自动生成本机密码；bootstrap 仅限空用户库，已有库不要重复。build-local 只构建，不运行测试。
打开 http://127.0.0.1:15173/ 。管理员从右上角登录进入管理概览，也可访问 /admin.html 使用登录入口。
数据库默认13306、后端18080；若后端端口改动，前端启动前设置 DAYU_BACKEND_URL（只允许本机HTTP）。

## 2. 数据和产品配置不是 Git 的一部分

Git 不包含数据库、样本、.env、管理员密码、本机色标配置或索引。新机空结果是预期状态，不要复制旧电脑 tmp 进程文件或 Docker 卷。

在 .env.local 填本机实际目录：

```text
DAYU_NETCDF_ROOT=D:\Dayu-dev-data\netcdf
DAYU_WEBP_ROOT=D:\Dayu-dev-data\WebP_V2_Dpi500_4KM
DAYU_COLORBAR_ROOT=D:\Dayu-dev-data\public
```

- NC根下面是 realtime/ 与 forecast/批次/；WebP根同样保留 realtime/产品/ 与 forecast/批次/产品/。
- 色标根为 CPP_Colorbar/ 或 colorbars/ 的父目录。例如文件 public/CPP_Colorbar/horizontal/BT108_Colorbar.webp 对应产品字段 CPP_Colorbar/horizontal/BT108_Colorbar.webp，不填绝对路径。
- 配置路径后重启后端，在产品资料中设置已有、已确认的色标文件。不要为了通过校验填虚构路径。
- 初始化清单生成17个产品、29条模式、15个发布，PLP/PRECIP缺必要色标时保留草稿。真实配置完成后由管理员明确发布；不要在代码中强制绕过。
- 手动扫描需确认，会修改索引，不删除原文件；查看任务明细和错误，再查询数据。
- 历史WebP受默认3天窗口限制。仅为历史样本调试，可在启动进程设置 `$env:DAYU_PREVIEW_RETENTION='400d'`，随后运行 start-local；结束后移除环境变量并重启恢复默认。不要改文件日期或把调试窗口写入生产默认值。
- NC历史检索独立于WebP预览窗口。一个NC可对应多种产品；同一个文件不要人为重复复制成不同产品。

## 3. Qwen

将 .env.example 复制为 .env，填写本机 DASHSCOPE_API_KEY，按需启用 DAYU_COPILOT_ENABLED。模型由 DAYU_COPILOT_QWEN_MODEL 配置，默认 qwen3.8-flash。
重启后端时不加 -DisableCopilot；启动本身不调用模型。只在页面发送问题时发起请求，别提交密钥到Git。
AI不能直接下载或修改后台。它可以建议查询条件，用户点击后进入普通检索、预览或产品说明。

## 4. 真实验收清单

- [ ] 目录/模式/单位/色标符合真实产品；草稿不向访客公开。
- [ ] 亮温、云、降水 WebP 能显示；云裁边定位和降水三时效/完成标记单独验证。
- [ ] 注册、登录、刷新保持身份、退出、普通用户访问管理接口被拒绝。
- [ ] NC按UTC/北京时间范围检索；预报 cycleTime/validTime/lead 正确。
- [ ] 未登录选文件后登录仍保留条件；用途10～2000字符；授权内容端点下载字节数和SHA256与源文件一致。
- [ ] 授权审计记录用户/文件/用途正确，不把授权量当下载完成量。
- [ ] 手动扫描/重复扫描/缺失文件与错误明细符合规则（在专用可恢复样本目录测试）。
- [ ] 用户/角色和产品状态写操作用专用测试对象，不禁用唯一管理员，不改生产数据。
- [ ] Qwen真实查询和不可用降级；AI建议必须用户点击，不执行任意URL或管理动作。

## 5. 生产环境仍需单独验收

本机开发代理不是生产服务器。部署前配置HTTPS、Cookie Secure、反向代理、受控NC下载、日志和数据备份；Nginx模板未自动部署。生产大文件/断点续传/权限失效以及云/降水空间精度不能由模拟测试或一次本地下载替代。
后端全量：在 backend/ 使用 Java17 执行 `./mvnw.cmd '-DargLine=-Xmx512m' '-Ddebug=false' verify`，Docker需运行。不能把跳过集成测试当作通过。
