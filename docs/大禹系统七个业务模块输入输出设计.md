# 大禹系统七个业务模块输入输出设计

> 状态：MS1 模块设计草案  
> 整理日期：2026-09-29  
> 上位文档：[大禹系统 MS1 架构决策草案](大禹系统MS1架构决策草案.md)  
> 目的：明确七个业务模块分别负责什么、接收什么、输出什么、执行什么行为，以及模块之间如何协作。本文不包含具体 Java 实现和数据库 DDL。

---

## 1. 总体模块划分

七个业务模块：

```text
Catalog       产品定义
AssetIndex    文件索引
Discovery     WebP/NC 数据查询
Identity      用户身份与登录
Download      下载授权与审计
Operations    管理员运维与监控
Copilot       AI 自然语言查询
```

以下内容不作为独立业务模块：

```text
LegacyAdapter   旧 PHP URL 兼容接入层
Infrastructure  MySQL、Redis、文件系统、Nginx、AI模型适配
```

总体依赖原则：

- Controller 不承载业务规则；
- 业务模块不直接依赖具体 MySQL、Redis、Nginx 实现；
- Discovery 不扫描硬盘；
- Download 不负责搜索文件和传输大文件；
- Copilot 不直接访问数据库或文件系统；
- Operations 负责协调，不复制其他模块的业务逻辑；
- 模块之间避免循环依赖。

## 2. Catalog：产品目录模块

### 2.1 职责

Catalog 负责管理系统中定义了哪些气象产品，以及产品的名称、分类、来源、展示信息和生命周期。

它回答：

> 系统支持哪些产品，这些产品如何描述，是否已经向用户发布？

### 2.2 输入

公开查询输入：

- 查询所有已发布产品；
- 根据稳定的产品编码查询一个产品。

管理员命令输入：

- 创建产品所需的产品编码、中英文名称、产品族、单位、说明和来源信息；
- 修改已有产品的可变资料；
- 发布一个完整的草稿产品；
- 停用一个已经发布的产品。

产品来源信息可以包括：

```text
生产者
算法名称
来源说明
FY-4B官方原始数据入口
```

### 2.3 输出

公开查询输出：

- 产品编码；
- 中英文名称；
- 产品族；
- 单位和说明；
- 生产者和算法名称；
- 来源说明与官方链接；
- 产品状态和显示顺序；
- 色标等展示配置。

管理员命令输出：

- 创建或修改后的产品；
- 发布或停用结果；
- 校验失败原因；
- 管理审计标识。

### 2.4 主要行为

创建产品时：

```text
校验产品编码唯一
→ 校验必填资料
→ 创建为DRAFT
```

修改产品时：

- 允许修改名称、单位、说明、来源、排序和展示配置；
- 产品编码作为稳定标识，创建后不应随意修改；
- 普通修改操作不能直接改变生命周期状态。

发布产品时：

```text
DRAFT
→ 校验公开资料和必要展示配置
→ PUBLISHED
→ 记录publishedAt和管理员审计
→ 清除产品目录缓存
```

停用产品时：

```text
PUBLISHED
→ DISABLED
→ 停止公开展示
→ 保留历史资产和下载审计
```

产品状态：

```text
DRAFT
PUBLISHED
DISABLED
```

### 2.5 明确不负责

- 不扫描硬盘；
- 不判断产品是否有 WebP 或 NC；
- 不生成时间轴；
- 不搜索历史数据；
- 不执行下载；
- 产品已发布不代表文件一定存在。

### 2.6 代码接口草案

```java
listPublishedProducts()
getProduct(productCode)
createProduct(CreateProductCommand)
updateProduct(UpdateProductCommand)
publishProduct(PublishProductCommand)
disableProduct(DisableProductCommand)
```

主要输入输出类型：

```text
CreateProductCommand
UpdateProductCommand
PublishProductCommand
DisableProductCommand
ProductSummary
ProductDetail
```

## 3. AssetIndex：文件索引模块

### 3.1 职责

AssetIndex 负责识别服务器硬盘上真实存在的 WebP 和 NetCDF 文件，并将可以查询的文件信息写入数据库索引。

它回答：

> 硬盘上现在真实存在什么文件，这些文件属于什么产品和时间？

### 3.2 输入

- WebP 根目录配置；
- NetCDF 根目录配置；
- 首次全量扫描请求；
- 定时增量扫描请求；
- 管理员立即增量扫描请求；
- 文件命名解析规则；
- 文件族与产品的映射配置；
- 当前配置的 WebP DPI，第一版默认为 Dpi500。

文件族映射示例：

```text
BT.nc      → 七个亮温产品
CPP.nc     → 六个云产品
PRECIP.nc  → PLP、PRECIP
```

### 3.3 输出

对数据库的输出：

- 新增或更新的文件资产；
- 文件与产品的关联关系；
- 已清理 WebP 对应的索引移除；
- 丢失 NC 对应的异常状态；
- 索引时间和文件修改时间。

一次扫描的结果输出：

```text
扫描开始和结束时间
扫描文件数
新增资产数
更新资产数
移除资产数
缺失NC数量
异常文件数
受影响产品
错误明细
```

对缓存的输出：

- 受影响产品列表，用于删除相关最新批次和 WebP 时间轴缓存。

### 3.4 主要行为

```text
扫描正式发布目录
→ 校验扩展名和文件名
→ 解析产品族
→ 解析实况/预报
→ 解析起报时间、有效时间和预报时效
→ 获取大小和修改时间
→ 幂等写入文件索引
→ 建立文件与产品关联
→ 清除受影响缓存
→ 返回扫描报告
```

幂等规则：

- 同一存储空间内 `relativePath` 唯一；
- 重复扫描不能重复插入；
- 已存在文件只更新发生变化的信息。

文件消失规则：

```text
WebP不存在 → 移除对应文件索引
NC不存在   → 标记MISSING、禁止下载并提醒管理员
```

扫描触发规则：

- 首次部署建立全量索引；
- 运行中按可配置 fixed delay 增量扫描；
- 管理员“立即扫描”和定时任务调用同一个增量扫描能力；
- 全量重建保留为内部维护能力，第一版不必暴露给页面。

### 3.5 明确不负责

- 不生成 WebP 或 NC；
- 不读取或解释 NC 内部科学变量；
- 不修改科学数据；
- 不删除硬盘文件；
- 不处理用户数据查询；
- 不执行下载。

### 3.6 代码接口草案

```java
runInitialFullScan()
runIncrementalScan(ScanTrigger trigger)
rebuildIndex()                       // 内部维护能力
```

主要输入输出类型：

```text
ScanTrigger：STARTUP / SCHEDULED / MANUAL
AssetScanResult
AssetScanError
AffectedProduct
```

## 4. Discovery：数据发现与查询模块

### 4.1 职责

Discovery 根据产品、数据模式和时间条件，从数据库索引中查询用户可以预览或可以申请下载的数据。

它回答：

> 用户现在能预览什么，历史上有哪些 NetCDF 科学数据可以申请下载？

### 4.2 输入

产品条件：

- 产品编码，如 `BT855`、`CTH`、`PRECIP`。

数据模式：

- 实况 `REALTIME`；
- 预报 `FORECAST`。

时间条件：

- UTC 起始时间；
- UTC 结束时间；
- 起报时间，可选；
- 预报时效，可选。

分页条件：

- 页码；
- 每页数量；
- 排序方向。

前端负责将用户选择的显示时区转换成 UTC 后再提交。

### 4.3 输出

#### 近期 WebP 帧

```text
WebP资产ID
公开预览URL
有效时间
起报时间
预报时效
是否存在可下载NC
```

用于 Cesium 图层和时间轴。结果按有效时间正序排列，便于播放，并限制最大帧数。

#### 可用预报批次

```text
起报时间
该批次有效时间范围
可用预报时效
是否完整
```

未指定起报批次时，默认使用最新完整批次。

#### 历史 NC 检索结果

```text
assetId
文件名
文件大小
关联产品
数据模式
有效时间
起报时间
预报时效
可用状态
```

历史 NC 强制分页，默认按有效时间从新到旧排列，不返回服务器物理路径。

#### 当前预览对应的 NC 候选

可能输出：

```text
一个候选NC
多个候选NC
没有候选NC
```

Discovery 只返回候选，不开始下载。

#### 产品可用状态

```text
是否有近期WebP
是否有历史NC
最新有效时间
最新预报批次
正常/延迟/缺失
```

### 4.4 主要行为

- 检查产品是否存在并已经发布；
- 从 Redis 查询可缓存的近期结果；
- 缓存未命中时查询 MySQL 文件索引；
- 实况按有效时间查询；
- 预报默认按有效时间查询，可进一步限定起报时间和预报时效；
- WebP 只查询近期窗口；
- NC 允许历史时间范围查询；
- 根据产品和时间为当前 WebP 查找 NC 候选；
- 根据文件索引计算产品当前预览、下载和更新状态。

### 4.5 明确不负责

- 不扫描硬盘；
- 不修改产品定义；
- 不执行文件下载；
- 不判断用户是否有下载权限；
- 不解析 NC；
- 不返回服务器物理路径。

### 4.6 代码接口草案

```java
listPreviewFrames(PreviewQuery)
listForecastCycles(ForecastCycleQuery)
searchScientificAssets(ScientificAssetQuery)
findDownloadCandidatesForPreview(PreviewDownloadQuery)
getProductAvailability(ProductAvailabilityQuery)
```

主要输入输出类型：

```text
PreviewQuery
ForecastCycleQuery
ScientificAssetQuery
PreviewDownloadQuery
ProductAvailabilityQuery
PreviewFrame
ForecastCycleSummary
ScientificAssetSummary
DownloadCandidate
ProductAvailability
PagedResult<T>
```

## 5. Identity：用户身份与登录模块

### 5.1 职责

Identity 负责用户注册、登录、Session、退出、当前身份、角色和账号状态。

它回答：

> 当前请求是谁发起的，该账号是否有效，具有什么角色？

### 5.2 输入

用户注册：

```text
邮箱
密码
工作单位
```

用户登录：

```text
邮箱
密码
客户端IP
```

查询身份：

- 浏览器自动携带的 Session Cookie。

退出登录：

- 当前 Session；
- CSRF Token。

管理员账号管理：

```text
目标用户ID
启用或禁用状态
角色调整
当前管理员身份
```

### 5.3 输出

注册或登录成功：

```text
是否已登录
用户ID
邮箱
工作单位
角色
CSRF Token
安全Session Cookie
```

查询当前身份：

- 已登录时返回公开用户信息；
- 未登录时返回明确的未认证状态。

禁止输出：

- 密码；
- 密码哈希；
- 数据库内部安全字段；
- 其他用户的资料。

### 5.4 主要行为

注册：

```text
校验邮箱和工作单位
→ 检查邮箱唯一
→ 校验密码规则
→ 哈希密码
→ 创建普通用户
→ 创建Session并自动登录
```

登录：

```text
检查Redis登录失败次数
→ 查询用户
→ 检查账号状态
→ 验证密码哈希
→ 重新生成Session ID
→ 建立登录状态
```

登录失败统一返回“邮箱或密码错误”，避免泄露邮箱是否存在。达到失败阈值时返回 HTTP 429。

退出：

```text
销毁Session
→ 清除Cookie
```

账号禁用后不得再次登录，已有 Session 应失效或在敏感操作时被拒绝。

### 5.5 明确不负责

- 不处理产品和文件查询；
- 不决定某个 NC 是否可下载；
- 不执行下载；
- 不保存明文密码；
- 不通过前端隐藏按钮代替后端权限检查。

### 5.6 代码接口草案

```java
register(RegisterCommand)
login(LoginCommand)
logout()
getCurrentUser()
changeUserStatus(ChangeUserStatusCommand)
changeUserRole(ChangeUserRoleCommand)
```

主要输入输出类型：

```text
RegisterCommand
LoginCommand
ChangeUserStatusCommand
ChangeUserRoleCommand
AuthenticatedUser
AuthenticationStatus
```

Session Cookie、CSRF 和安全上下文由 Spring Security 接入层协助管理。

## 6. Download：下载授权与审计模块

### 6.1 职责

Download 负责检查当前用户是否可以下载指定 NetCDF，记录用途和授权审计，并生成交给 Nginx 的内部下载授权。

它回答：

> 当前用户能否下载这个文件，应记录什么审计信息，Nginx 应发送哪个文件？

### 6.2 输入

前端提交：

```text
assetId
数据使用目的
```

后端安全上下文和请求环境提供：

```text
当前用户ID
当前角色
工作单位
IP
User-Agent
Session
CSRF Token
```

前端不得提交用户 ID、角色、工作单位或服务器文件路径。

### 6.3 输出

授权成功时，内部输出：

```text
downloadEventId
下载文件名
Content-Type
文件大小
Nginx内部下载位置
```

Nginx 根据内部位置发送文件，服务器物理路径不暴露给前端 JavaScript。

授权失败时，输出明确但安全的错误：

```text
未登录
账号不可用
用途不符合要求
文件不存在
文件当前不可下载
没有权限
请求过于频繁
```

### 6.4 主要行为

```text
检查登录和账号状态
→ 校验10～2000字符用途
→ 根据assetId查询文件资产
→ 确认类型为NETCDF且状态AVAILABLE
→ 验证真实文件存在和路径安全
→ 写入AUTHORIZED审计记录
→ 返回X-Accel-Redirect所需内部信息
→ Nginx传输文件
```

路径校验必须防止：

- 绝对路径注入；
- `.` 和 `..`；
- 控制字符；
- 逃逸 NetCDF 根目录；
- 符号链接指向根目录之外。

审计记录包括：

```text
downloadEventId
userId
工作单位快照
assetId
产品快照
文件名和预期大小
用途
IP
User-Agent
AUTHORIZED状态
授权时间
```

第一版不把授权成功描述成客户端已完整保存。未来可以通过 Nginx 日志补充发送字节数和传输结果。

### 6.5 明确不负责

- 不搜索 NC；
- 不接受前端文件路径；
- 不把整个 NC 加载到 Java 内存；
- 生产环境不由 Java 持续传输大文件；
- 不证明用户一定已将文件保存到本地硬盘。

### 6.6 代码接口草案

```java
authorizeDownload(DownloadCommand, AuthenticatedUser, ClientContext)
recordDeliveryResult(DeliveryResultCommand)  // 后续扩展
```

主要输入输出类型：

```text
DownloadCommand
ClientContext
DownloadGrant
DownloadDenied
DeliveryResultCommand
```

`DownloadCommand` 只包含：

```text
assetId
purpose
```

## 7. Operations：管理员运维与监控模块

### 7.1 职责

Operations 为管理员提供系统运行状态、产品数据健康状态、索引扫描结果、下载审计和统计，并协调其他业务模块完成管理动作。

它回答：

> 系统目前是否正常，哪些产品缺失或延迟，最近扫描是否成功，数据如何被申请下载？

### 7.2 输入

管理仪表盘查询：

```text
统计时间范围
产品筛选
实况/预报筛选
当前管理员身份
```

索引操作：

```text
立即增量扫描请求
当前管理员身份
```

下载审计查询：

```text
起止时间
产品
用户
工作单位
授权状态
分页条件
```

用户管理：

```text
目标用户ID
启用/禁用
角色调整
```

### 7.3 输出

管理仪表盘：

```text
已发布产品数
当前可预览产品数
当前可下载产品数
数据缺失产品数
数据延迟产品数
最近扫描时间和结果
下载申请和授权数量
```

产品健康状态：

```text
产品
实况/预报
WebP数量
NC数量
最新有效时间
距离现在多久
正常/延迟/缺失
```

扫描状态：

```text
扫描开始和结束时间
新增、更新、移除数量
缺失NC数量
异常文件列表
```

下载审计和统计：

```text
用户和工作单位快照
产品和文件
用途
授权时间
状态
按产品/机构/用户聚合的数量
```

所有明细列表必须分页。

### 7.4 主要行为

Operations 通过协调其他模块完成工作：

```text
Catalog      产品生命周期
AssetIndex   触发扫描并读取扫描结果
Discovery    产品可用状态
Identity     用户状态与角色
Download     下载审计和统计
```

产品健康状态依据产品模式策略判断：

```text
productId
dataMode：REALTIME / FORECAST
enabled
staleAfterMinutes
```

同一 Product 的实况和预报可以配置不同的延迟阈值。

### 7.5 明确不负责

- 不删除物理数据文件；
- 不启动或停止系统服务；
- 不修改 Nginx 配置；
- 不执行数据库迁移；
- 不运行气象算法；
- 不复制 Catalog、AssetIndex、Identity 或 Download 的内部规则。

### 7.6 代码接口草案

```java
getDashboard(OperationsQuery)
getProductHealth(ProductHealthQuery)
triggerIncrementalScan()
searchDownloadAudits(DownloadAuditQuery)
getDownloadStatistics(DownloadStatisticsQuery)
changeUserStatus(ChangeUserStatusCommand)
```

主要输入输出类型：

```text
OperationsQuery
ProductHealthQuery
DownloadAuditQuery
DownloadStatisticsQuery
DashboardSummary
ProductHealth
DownloadAuditSummary
DownloadStatistics
PagedResult<T>
```

## 8. Copilot：AI 气象数据助手模块

### 8.1 职责

Copilot 将用户自然语言转换成经过校验的结构化查询条件，调用 Catalog 和 Discovery 获取真实结果，再向用户解释结果。

它回答：

> 用户想查询什么产品、什么时间和什么数据模式，系统中是否真的存在这些数据？

### 8.2 输入

```text
用户自然语言
用户当前显示时区
当前页面选择的产品（可选）
当前正在查看的时间（可选）
当前是否已登录及公开角色信息
最近少量对话上下文（可选）
```

禁止输入：

```text
密码或密码哈希
Session ID
数据库凭据
其他用户资料
历史下载用途
NC文件内容
```

### 8.3 输出

查询成功：

```text
对用户意图的简短理解
结构化查询条件
基于真实业务查询的结果
建议前端执行的动作
```

条件不明确：

- 返回一个必要的澄清问题，例如询问实况或预报。

没有数据：

- 明确返回该条件下没有可用数据，不编造文件。

AI 不可用：

- 返回可降级状态，引导用户使用普通搜索。

### 8.4 主要行为

```text
理解自然语言
→ 生成结构化查询条件
→ Java再次校验和归一化
→ 调用Catalog确认产品
→ 调用Discovery查询真实数据
→ 根据真实结果生成回答
```

Copilot 可以：

- 查询产品目录；
- 查询近期 WebP；
- 查询历史 NC；
- 查询可用预报批次；
- 返回“查看结果”或“申请下载”的前端建议动作。

Copilot 不可以：

- 直接访问 MySQL、Redis 或硬盘；
- 自行拼接 SQL；
- 执行下载；
- 代替用户填写用途；
- 绕过登录；
- 调用管理员能力；
- 修改产品和文件索引。

第一版只保留当前问题、页面上下文和最近少量对话，不建立长期聊天记录和用户画像。

### 8.5 明确不负责

- 不作为新的数据事实来源；
- 不替代普通产品浏览和搜索；
- 不执行有副作用的管理或下载操作；
- 不保存敏感上下文；
- 不解析 NC 科学内容。

### 8.6 代码接口草案

```java
query(CopilotCommand)
```

主要输入输出类型：

```text
CopilotCommand
PageContext
InterpretedCriteria
CopilotResponse
SuggestedAction
```

Copilot 内部可使用的受控工具接口：

```java
listProducts()
listPreviewFrames()
searchScientificAssets()
listForecastCycles()
```

## 9. 七个模块之间的主流程

### 9.1 文件进入索引

```text
上游发布WebP/NC
→ AssetIndex扫描和解析
→ 写入文件索引和产品关联
→ 失效Redis查询缓存
```

### 9.2 用户浏览 WebP

```text
前端选择产品和时间
→ Discovery查询近期帧
→ Redis命中或查询MySQL
→ 返回有序WebP URL
→ 前端预加载并交给Cesium展示
```

### 9.3 用户历史检索和下载 NC

```text
前端提交产品和时间条件
→ Discovery分页返回NC摘要和assetId
→ 用户点击下载并填写用途
→ Identity提供当前身份
→ Download执行授权、路径校验和审计
→ Nginx传输NC
```

### 9.4 管理员查看系统状态

```text
管理员进入后台
→ Identity确认ADMIN
→ Operations组合产品、索引、可用性和审计数据
→ 返回管理仪表盘
```

### 9.5 AI 查询

```text
用户输入自然语言
→ Copilot生成并校验查询条件
→ 调用Catalog和Discovery
→ 返回真实结果和前端建议动作
```
