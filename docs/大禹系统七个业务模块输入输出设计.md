# 大禹系统七个业务模块输入输出设计

> 状态：MS1 模块设计草案  
> 整理日期：2026-09-29  
> 上位文档：[大禹系统 MS1 架构决策草案](大禹系统MS1架构决策草案.md)  
> 目的：明确七个业务模块分别负责什么、接收什么、输出什么、执行什么行为，以及模块之间如何协作。本文不包含具体 Java 实现和数据库 DDL。

---

## 1. 总体模块划分

七个业务模块：

```text
Catalog       产品定义
AssetIndex    文件索引
Discovery     WebP/NC 数据查询
Identity      用户身份与登录
Download      下载授权与审计
Operations    管理员运维与监控
Copilot       AI 自然语言查询
```

以下内容不作为独立业务模块：

```text
LegacyAdapter   旧 PHP URL 兼容接入层
Infrastructure  MySQL、Redis、文件系统、Nginx、AI模型适配
```

总体依赖原则：

- Controller 不承载业务规则；
- 业务模块不直接依赖具体 MySQL、Redis、Nginx 实现；
- Discovery 不扫描硬盘；
- Download 不负责搜索文件和传输大文件；
- Copilot 不直接访问数据库或文件系统；
- Operations 负责协调，不复制其他模块的业务逻辑；
- 模块之间避免循环依赖。

## 2. Catalog：产品目录模块

### 2.1 职责

Catalog 负责管理系统中定义了哪些气象产品，以及产品的名称、分类、来源、展示信息和生命周期。

它回答：

> 系统支持哪些产品，这些产品如何描述，是否已经向用户发布？

### 2.2 输入

公开查询输入：

- 查询所有已发布产品；
- 根据稳定的产品编码查询一个产品。

管理员查询输入：

- 查询草稿、已发布和已停用的全部产品；
- 按产品族、状态或编码筛选；
- 查询文件族应关联的产品清单，供 AssetIndex 建立映射。

管理员命令输入：

- 创建产品所需的产品编码、中英文名称、产品族、单位、说明和来源信息；
- 修改已有产品的可变资料；
- 发布一个完整的草稿产品；
- 停用一个已经发布的产品。

产品来源信息可以包括：

```text
生产者
算法名称
来源说明
FY-4B官方原始数据入口
```

### 2.3 输出

公开查询输出：

- 产品编码；
- 中英文名称；
- 产品族；
- 单位和说明；
- 生产者和算法名称；
- 来源说明与官方链接；
- 产品状态和显示顺序；
- 色标等展示配置。

管理员命令输出：

- 创建或修改后的产品；
- 发布或停用结果；
- 校验失败原因；
- 管理审计标识。

管理员查询输出：

- 包含 `DRAFT/PUBLISHED/DISABLED` 的产品列表；
- 文件族到产品的映射，例如 `BT → 七个亮温产品`；
- 产品模式策略，例如实况/预报是否启用及延迟阈值。

### 2.4 主要行为

创建产品时：

```text
校验产品编码唯一
→ 校验必填资料
→ 创建为DRAFT
```

修改产品时：

- 允许修改名称、单位、说明、来源、排序和展示配置；
- 产品编码作为稳定标识，创建后不应随意修改；
- 普通修改操作不能直接改变生命周期状态。

发布产品时：

```text
DRAFT
→ 校验公开资料和必要展示配置
→ PUBLISHED
→ 记录publishedAt和管理员审计
→ 清除产品目录缓存
```

停用产品时：

```text
PUBLISHED
→ DISABLED
→ 停止公开展示
→ 保留历史资产和下载审计
```

产品状态：

```text
DRAFT
PUBLISHED
DISABLED
```

### 2.5 明确不负责

- 不扫描硬盘；
- 不判断产品是否有 WebP 或 NC；
- 不生成时间轴；
- 不搜索历史数据；
- 不执行下载；
- 产品已发布不代表文件一定存在。

### 2.6 代码接口草案

```java
listPublishedProducts()
listManagedProducts(ManagedProductQuery)
getProduct(productCode)
resolveProductsForAssetFamily(assetFamilyCode)
createProduct(CreateProductCommand)
updateProduct(UpdateProductCommand)
publishProduct(PublishProductCommand)
disableProduct(DisableProductCommand)
```

主要输入输出类型：

```text
CreateProductCommand
UpdateProductCommand
PublishProductCommand
DisableProductCommand
ProductSummary
ProductDetail
ManagedProductSummary
AssetFamilyProductMapping
```

## 3. AssetIndex：文件索引模块

### 3.1 职责

AssetIndex 负责识别服务器硬盘上真实存在的 WebP 和 NetCDF 文件，并将可以查询的文件信息写入数据库索引。

它回答：

> 硬盘上现在真实存在什么文件，这些文件属于什么产品和时间？

### 3.2 输入

- WebP 根目录配置；
- NetCDF 根目录配置；
- 首次全量扫描请求；
- 定时增量扫描请求；
- 管理员立即增量扫描请求；
- 文件命名解析规则；
- 文件族与产品的映射配置；
- 当前配置的 WebP DPI，第一版默认为 Dpi500。

文件族映射示例：

```text
BT.nc      → 七个亮温产品
CPP.nc     → 六个云产品
PRECIP.nc  → PLP、PRECIP
```

### 3.3 输出

对数据库的输出：

- 新增或更新的文件资产；
- 文件与产品的关联关系；
- 已清理 WebP 对应的索引移除；
- 丢失 NC 对应的异常状态；
- 索引时间和文件修改时间。

一次扫描的结果输出：

```text
扫描开始和结束时间
扫描文件数
新增资产数
更新资产数
移除资产数
缺失NC数量
异常文件数
受影响产品
错误明细
```

对缓存的输出：

- 受影响产品列表，用于删除相关最新批次和 WebP 时间轴缓存。

对其他业务模块提供的受限读取输出：

- 给 Discovery：适合预览、预报批次和历史 NC 查询的索引记录；
- 给 Download：包含受控相对路径、文件类型、状态和预期大小的下载资产；
- 给 Operations：最近扫描结果和分页扫描历史。

这些接口提供不同的信息范围。普通查询不能获得下载内部路径，Download 也不能绕过 AssetIndex 直接访问其数据库实现。

### 3.4 主要行为

```text
扫描正式发布目录
→ 校验扩展名和文件名
→ 解析产品族
→ 解析实况/预报
→ 解析起报时间、有效时间和预报时效
→ 获取大小和修改时间
→ 幂等写入文件索引
→ 建立文件与产品关联
→ 清除受影响缓存
→ 返回扫描报告
```

幂等规则：

- 同一存储空间内 `relativePath` 唯一；
- 重复扫描不能重复插入；
- 已存在文件只更新发生变化的信息。

文件消失规则：

```text
WebP不存在 → 移除对应文件索引
NC不存在   → 标记MISSING、禁止下载并提醒管理员
```

扫描触发规则：

- 首次部署建立全量索引；
- 运行中按可配置 fixed delay 增量扫描；
- 管理员“立即扫描”和定时任务调用同一个增量扫描能力；
- 全量重建保留为内部维护能力，第一版不必暴露给页面。

### 3.5 明确不负责

- 不生成 WebP 或 NC；
- 不读取或解释 NC 内部科学变量；
- 不修改科学数据；
- 不删除硬盘文件；
- 不处理用户数据查询；
- 不执行下载。

### 3.6 代码接口草案

```java
runInitialFullScan()
runIncrementalScan(ScanTrigger trigger)
rebuildIndex()                       // 内部维护能力

// 提供给Discovery的只读接口
listPreviewAssets(AssetPreviewCriteria)
listForecastCycles(AssetForecastCycleCriteria)
searchNetcdfAssets(AssetSearchCriteria)
findNetcdfCandidates(AssetMatchCriteria)

// 提供给Download的受限接口
findDownloadableAsset(assetId)

// 提供给Operations的管理查询接口
getLatestScanResult()
searchScanHistory(ScanHistoryQuery)
```

主要输入输出类型：

```text
ScanTrigger：STARTUP / SCHEDULED / MANUAL
AssetScanResult
AssetScanError
AffectedProduct
IndexedAssetView
DownloadableAsset
ScanHistoryQuery
ScanHistorySummary
```

## 4. Discovery：数据发现与查询模块

### 4.1 职责

Discovery 根据产品、数据模式和时间条件，从数据库索引中查询用户可以预览或可以申请下载的数据。

它回答：

> 用户现在能预览什么，历史上有哪些 NetCDF 科学数据可以申请下载？

### 4.2 输入

产品条件：

- 产品编码，如 `BT855`、`CTH`、`PRECIP`。

数据模式：

- 实况 `REALTIME`；
- 预报 `FORECAST`。

时间条件：

- UTC 起始时间；
- UTC 结束时间；
- 起报时间，可选；
- 预报时效，可选。

分页条件：

- 页码；
- 每页数量；
- 排序方向。

前端负责将用户选择的显示时区转换成 UTC 后再提交。

### 4.3 输出

#### 近期 WebP 帧

```text
WebP资产ID
公开预览URL
有效时间
起报时间
预报时效
是否存在可下载NC
```

用于 Cesium 图层和时间轴。结果按有效时间正序排列，便于播放，并限制最大帧数。

#### 可用预报批次

```text
起报时间
该批次有效时间范围
可用预报时效
是否完整
```

未指定起报批次时，默认使用最新完整批次。

#### 历史 NC 检索结果

```text
assetId
文件名
文件大小
关联产品
数据模式
有效时间
起报时间
预报时效
可用状态
```

历史 NC 强制分页，默认按有效时间从新到旧排列，不返回服务器物理路径。

#### 当前预览对应的 NC 候选

可能输出：

```text
一个候选NC
多个候选NC
没有候选NC
```

Discovery 只返回候选，不开始下载。

#### 产品可用状态

```text
是否有近期WebP
是否有历史NC
最新有效时间
最新预报批次
正常/延迟/缺失
```

管理员仪表盘需要一次查询多个产品，因此还应支持批量输出产品可用状态，避免 Operations 对每个产品逐个发起查询。

### 4.4 主要行为

- 检查产品是否存在并已经发布；
- 从 Redis 查询可缓存的近期结果；
- 缓存未命中时查询 MySQL 文件索引；
- 实况按有效时间查询；
- 预报默认按有效时间查询，可进一步限定起报时间和预报时效；
- WebP 只查询近期窗口；
- NC 允许历史时间范围查询；
- 根据产品和时间为当前 WebP 查找 NC 候选；
- 根据文件索引计算产品当前预览、下载和更新状态。

### 4.5 明确不负责

- 不扫描硬盘；
- 不修改产品定义；
- 不执行文件下载；
- 不判断用户是否有下载权限；
- 不解析 NC；
- 不返回服务器物理路径。

### 4.6 代码接口草案

```java
listPreviewFrames(PreviewQuery)
listForecastCycles(ForecastCycleQuery)
searchScientificAssets(ScientificAssetQuery)
findDownloadCandidatesForPreview(PreviewDownloadQuery)
getProductAvailability(ProductAvailabilityQuery)
listProductAvailability(ProductAvailabilityListQuery)
```

主要输入输出类型：

```text
PreviewQuery
ForecastCycleQuery
ScientificAssetQuery
PreviewDownloadQuery
ProductAvailabilityQuery
ProductAvailabilityListQuery
PreviewFrame
ForecastCycleSummary
ScientificAssetSummary
DownloadCandidate
ProductAvailability
PagedResult<T>
```

## 5. Identity：用户身份与登录模块

### 5.1 职责

Identity 负责用户注册、登录、Session、退出、当前身份、角色和账号状态。

它回答：

> 当前请求是谁发起的，该账号是否有效，具有什么角色？

### 5.2 输入

用户注册：

```text
邮箱
密码
工作单位
```

用户登录：

```text
邮箱
密码
客户端IP
```

查询身份：

- 浏览器自动携带的 Session Cookie。

退出登录：

- 当前 Session；
- CSRF Token。

管理员账号管理：

```text
目标用户ID
启用或禁用状态
角色调整
当前管理员身份
```

### 5.3 输出

注册或登录成功：

```text
是否已登录
用户ID
邮箱
工作单位
角色
CSRF Token
安全Session Cookie
```

查询当前身份：

- 已登录时返回公开用户信息；
- 未登录时返回明确的未认证状态。

禁止输出：

- 密码；
- 密码哈希；
- 数据库内部安全字段；
- 其他用户的资料。

### 5.4 主要行为

注册：

```text
校验邮箱和工作单位
→ 检查邮箱唯一
→ 校验密码规则
→ 哈希密码
→ 创建普通用户
→ 创建Session并自动登录
```

登录：

```text
检查Redis登录失败次数
→ 查询用户
→ 检查账号状态
→ 验证密码哈希
→ 重新生成Session ID
→ 建立登录状态
```

登录失败统一返回“邮箱或密码错误”，避免泄露邮箱是否存在。达到失败阈值时返回 HTTP 429。

退出：

```text
销毁Session
→ 清除Cookie
```

账号禁用后不得再次登录，已有 Session 应失效或在敏感操作时被拒绝。

### 5.5 明确不负责

- 不处理产品和文件查询；
- 不决定某个 NC 是否可下载；
- 不执行下载；
- 不保存明文密码；
- 不通过前端隐藏按钮代替后端权限检查。

### 5.6 代码接口草案

```java
register(RegisterCommand)
login(LoginCommand)
logout()
getCurrentUser()
changeUserStatus(ChangeUserStatusCommand)
changeUserRole(ChangeUserRoleCommand)
```

主要输入输出类型：

```text
RegisterCommand
LoginCommand
ChangeUserStatusCommand
ChangeUserRoleCommand
AuthenticatedUser
AuthenticationStatus
```

Session Cookie、CSRF 和安全上下文由 Spring Security 接入层协助管理。

## 6. Download：下载授权与审计模块

### 6.1 职责

Download 负责检查当前用户是否可以下载指定 NetCDF，记录用途和授权审计，并生成交给 Nginx 的内部下载授权。

它回答：

> 当前用户能否下载这个文件，应记录什么审计信息，Nginx 应发送哪个文件？

### 6.2 输入

前端提交：

```text
assetId
数据使用目的
```

后端安全上下文和请求环境提供：

```text
当前用户ID
当前角色
工作单位
IP
User-Agent
Session
CSRF Token
```

前端不得提交用户 ID、角色、工作单位或服务器文件路径。

管理员审计查询输入：

```text
时间范围
产品
用户或工作单位
审计状态
分页条件
```

### 6.3 输出

授权成功时，内部输出：

```text
downloadEventId
下载文件名
Content-Type
文件大小
Nginx内部下载位置
```

Nginx 根据内部位置发送文件，服务器物理路径不暴露给前端 JavaScript。

授权失败时，输出明确但安全的错误：

```text
未登录
账号不可用
用途不符合要求
文件不存在
文件当前不可下载
没有权限
请求过于频繁
```

### 6.4 主要行为

```text
检查登录和账号状态
→ 校验10～2000字符用途
→ 根据assetId查询文件资产
→ 确认类型为NETCDF且状态AVAILABLE
→ 验证真实文件存在和路径安全
→ 写入AUTHORIZED审计记录
→ 返回X-Accel-Redirect所需内部信息
→ Nginx传输文件
```

路径校验必须防止：

- 绝对路径注入；
- `.` 和 `..`；
- 控制字符；
- 逃逸 NetCDF 根目录；
- 符号链接指向根目录之外。

审计记录包括：

```text
downloadEventId
userId
工作单位快照
assetId
产品快照
文件名和预期大小
用途
IP
User-Agent
AUTHORIZED状态
授权时间
```

第一版不把授权成功描述成客户端已完整保存。未来可以通过 Nginx 日志补充发送字节数和传输结果。

管理员审计查询输出：

```text
下载事件ID
用户和工作单位快照
产品和文件快照
用途
授权时间
状态
分页信息
```

统计输出：

```text
申请数
授权数
拒绝数
按产品/机构/用户聚合数量
```

### 6.5 明确不负责

- 不搜索 NC；
- 不接受前端文件路径；
- 不把整个 NC 加载到 Java 内存；
- 生产环境不由 Java 持续传输大文件；
- 不证明用户一定已将文件保存到本地硬盘。

### 6.6 代码接口草案

```java
authorizeDownload(DownloadCommand, AuthenticatedUser, ClientContext)
recordDeliveryResult(DeliveryResultCommand)  // 后续扩展
searchDownloadAudits(DownloadAuditQuery)
getDownloadStatistics(DownloadStatisticsQuery)
```

主要输入输出类型：

```text
DownloadCommand
ClientContext
DownloadGrant
DownloadDenied
DeliveryResultCommand
DownloadAuditQuery
DownloadAuditSummary
DownloadStatisticsQuery
DownloadStatistics
PagedResult<T>
```

`DownloadCommand` 只包含：

```text
assetId
purpose
```

## 7. Operations：管理员运维与监控模块

### 7.1 职责

Operations 为管理员提供系统运行状态、产品数据健康状态、索引扫描结果、下载审计和统计，并协调其他业务模块完成管理动作。

它回答：

> 系统目前是否正常，哪些产品缺失或延迟，最近扫描是否成功，数据如何被申请下载？

### 7.2 输入

管理仪表盘查询：

```text
统计时间范围
产品筛选
实况/预报筛选
当前管理员身份
```

索引操作：

```text
立即增量扫描请求
当前管理员身份
```

下载审计查询：

```text
起止时间
产品
用户
工作单位
授权状态
分页条件
```

用户管理：

```text
目标用户ID
启用/禁用
角色调整
```

### 7.3 输出

管理仪表盘：

```text
已发布产品数
当前可预览产品数
当前可下载产品数
数据缺失产品数
数据延迟产品数
最近扫描时间和结果
下载申请和授权数量
```

产品健康状态：

```text
产品
实况/预报
WebP数量
NC数量
最新有效时间
```

## 8. Copilot：AI 气象数据助手模块

### 8.1 职责

Copilot 将用户自然语言转换成经过校验的结构化查询条件，调用 Catalog 和 Discovery 获取真实结果，再向用户解释结果。

它回答：

> 用户想查询什么产品、什么时间和什么数据模式，系统中是否真的存在这些数据？

### 8.2 输入

```text
用户自然语言
用户当前显示时区
当前页面选择的产品（可选）
当前正在查看的时间（可选）
当前是否已登录及公开角色信息
最近少量对话上下文（可选）
```

禁止输入：

```text
密码或密码哈希
Session ID
数据库凭据
其他用户资料
历史下载用途
NC文件内容
```

### 8.3 输出

查询成功：

```text
对用户意图的简短理解
结构化查询条件
基于真实业务查询的结果
建议前端执行的动作
```

条件不明确：

- 返回一个必要的澄清问题，例如询问实况或预报。

没有数据：

- 明确返回该条件下没有可用数据，不编造文件。

AI 不可用：

- 返回可降级状态，引导用户使用普通搜索。

### 8.4 主要行为

```text
理解自然语言
→ 生成结构化查询条件
→ Java再次校验和归一化
→ 调用Catalog确认产品
→ 调用Discovery查询真实数据
→ 根据真实结果生成回答
```

Copilot 可以：

- 查询产品目录；
- 查询近期 WebP；
- 查询历史 NC；
- 查询可用预报批次；
- 返回“查看结果”或“申请下载”的前端建议动作。

Copilot 不可以：

- 直接访问 MySQL、Redis 或硬盘；
- 自行拼接 SQL；
- 执行下载；
- 代替用户填写用途；
- 绕过登录；
- 调用管理员能力；
- 修改产品和文件索引。

第一版只保留当前问题、页面上下文和最近少量对话，不建立长期聊天记录和用户画像。

### 8.5 明确不负责

- 不作为新的数据事实来源；
- 不替代普通产品浏览和搜索；
- 不执行有副作用的管理或下载操作；
- 不保存敏感上下文；
- 不解析 NC 科学内容。

### 8.6 代码接口草案

```java
query(CopilotCommand)
```

主要输入输出类型：

```text
CopilotCommand
PageContext
InterpretedCriteria
CopilotResponse
SuggestedAction
```

Copilot 内部可使用的受控工具接口：

```java

```

## 9. 模块依赖方向

### 9.1 总体依赖关系

```text
Catalog                 Identity
   ▲                        ▲
   │                        │
AssetIndex                  │
   ▲                        │
   │                        │
Discovery ◄── Copilot      │
   ▲                        │
   │                        │
   └────── Operations ──────┘

AssetIndex ◄── Download ◄── Operations
Catalog    ◄─────────────── Operations
Discovery  ◄─────────────── Operations
```

依赖规则：

| 模块 | 允许依赖的业务模块 | 原因 |
| --- | --- | --- |
| Catalog | 无 | 产品定义是基础能力 |
| Identity | 无 | 用户身份可以独立运行 |
| AssetIndex | Catalog | 扫描文件后需要解析产品族映射 |
| Discovery | Catalog、AssetIndex | 校验已发布产品并读取文件索引 |
| Download | AssetIndex | 使用受限接口按 assetId 获取可下载文件 |
| Copilot | Catalog、Discovery | 理解产品并执行受控查询 |
| Operations | Catalog、AssetIndex、Discovery、Identity、Download | 汇总和编排管理员能力 |

### 9.2 Identity 与 Download 的关系

Download 不直接处理登录。Spring Security 在请求进入 Download 之前建立可信的 `AuthenticatedUser`：

```text
Spring Security
→ Identity建立用户身份和Session
→ Controller取得AuthenticatedUser
→ 作为可信参数传给Download
```

这样 Download 不依赖 Identity 的登录实现，但仍使用 Identity 产生的可信身份。

### 9.3 AssetIndex 的分级读取接口

AssetIndex 是文件索引的所有者，对不同模块暴露不同范围：

```text
AssetQueryService
→ 给Discovery，只返回查询需要的索引数据

DownloadAssetLookup
→ 给Download，允许读取受控路径和下载状态

AssetAdminQueryService
→ 给Operations，返回扫描结果和异常信息
```

其他模块不能直接调用 AssetIndex 内部 Repository 或 Mapper。

### 9.4 Operations 位于最上层

Operations 可以依赖多个模块，因为它负责管理员视角的编排。其他业务模块禁止反向依赖 Operations，从而避免循环依赖。

### 9.5 接入层依赖

```text
Public Controller
→ Catalog、Discovery、Identity、Download、Copilot

Admin Controller
→ Catalog、Operations

LegacyAdapter
→ Catalog、Discovery、Identity、Download
```

Controller 和 LegacyAdapter 只进行协议转换、参数校验和响应映射，不实现业务规则。

## 11. Java 工程总体决策

### 11.1 构建方式

第一版采用：

```text
单 Maven 工程
+ package-by-feature
+ ArchUnit 依赖约束
```

不为七个业务模块分别创建 Maven 子模块。原因：

- 当前项目规模不需要多模块 Maven 的构建复杂度；
- 单工程更容易启动、调试和运行测试；
- 业务边界通过 package、公开 API 和 ArchUnit 强制；
- 后续某个模块确实需要独立部署时，再根据稳定边界拆分。

基础工程信息暂定：

```text
Java：17
构建工具：Maven Wrapper
打包方式：可执行JAR
groupId：cn.edu.fudan
artifactId：dayu-platform-backend
基础包：cn.edu.fudan.dayu
```

Spring Boot 使用创建工程时适配 Java 17 的稳定 3.x 版本，具体补丁版本在生成骨架时锁定并记录，不使用浮动版本。

### 11.2 第一阶段最小依赖

空骨架阶段只引入：

```text
spring-boot-starter-web
spring-boot-starter-validation
spring-boot-starter-security
spring-boot-starter-test
archunit-junit5
```

第一阶段暂不引入：

```text
MyBatis/MyBatis-Plus
MySQL驱动
Redis
Spring Session Redis
AI模型SDK
MinIO
消息队列
```

这些依赖在相应端口和数据模型确认后按功能增量加入，避免空骨架阶段被基础设施实现干扰。

不使用 Lombok。优先使用 Java 17 `record`、显式构造器和不可变对象，让接口结构可以直接阅读。

### 12.2 各层含义

`api/`：

- 其他模块允许调用的 Java 接口；
- 跨模块 Command、Query、DTO；
- 对外稳定，不包含实现细节。

`application/`：

- 用例实现和流程编排；
- 定义本模块所需的 Repository、Cache、Storage 等出站端口；
- 可以使用 Spring 依赖注入，但不包含 HTTP 细节。

`domain/`：

- 领域对象、值对象、枚举和纯业务规则；
- 尽量保持纯 Java；
- 不依赖 Spring MVC、数据库和 Redis。

`infrastructure/`：

- 本模块 Repository、Redis、文件系统、Nginx 或模型端口的具体实现；
- 可以依赖第三方库；
- 不能成为其他业务模块的直接依赖。

`interfaces/rest/v1/`：

- 新 API Controller；
- HTTP 参数校验；
- HTTP DTO 与业务 DTO 的转换；
- 统一错误响应。

`interfaces/rest/legacy/`：

- 旧 `.php` URL 兼容 Controller；
- 只转换旧参数和旧响应格式；
- 必须复用同一业务 API。

`shared/kernel/`：

- 仅保存真正跨模块且稳定的基础概念；
- 禁止演变成通用工具和业务逻辑垃圾桶。

### 12.3 跨模块可见性

其他模块只允许依赖目标模块的 `api` 包。

允许：

```java
import cn.edu.fudan.dayu.catalog.api.CatalogQueryService;
```

禁止：

```java
import cn.edu.fudan.dayu.catalog.application.CatalogService;
import cn.edu.fudan.dayu.catalog.domain.Product;
import cn.edu.fudan.dayu.catalog.infrastructure.ProductMapper;
```

实现类在不需要跨包访问时优先使用 package-private。跨模块数据通过 `api` DTO 传递，不直接暴露领域实体和数据库实体。

## 13. Shared Kernel 最小类型

以下概念被多个模块共同使用，可以进入 `shared/kernel`：

```java
record ProductCode(String value) {}
record ProductId(long value) {}
record AssetId(long value) {}
record UserId(long value) {}
record DownloadEventId(long value) {}

enum DataMode { REALTIME, FORECAST }
enum AssetType { WEBP, NETCDF }
enum UserRole { USER, ADMIN }
```

跨模块分页结构：

```java
record PageRequest(int page, int size) {}
record PageResult<T>(List<T> items, int page, int size, long total) {}
```

可信请求身份使用中立类型，避免 Download 直接依赖 Identity 的内部模型：

```java
record ActorContext(
    UserId userId,
    String organization,
    UserRole role
) {}
```

`ActorContext` 只能由认证接入层根据 Spring Security 上下文创建，不能由前端请求体构造。

时间统一使用：

```text
Instant：绝对时间点
Duration：间隔和TTL
ZoneId：前端显示时区或用户偏好
```

禁止在后端领域接口中用无时区含义的 `LocalDateTime` 表示数据时刻。

### 14.5 Download API

```java
interface DownloadAuthorizationService {
    DownloadGrant authorizeDownload(
        DownloadCommand command,
        ActorContext actor,
        ClientContext client

}

interface DownloadAuditQueryService {
    PageResult<DownloadAuditSummary> searchDownloadAudits(DownloadAuditQuery query);
    DownloadStatistics getDownloadStatistics(DownloadStatisticsQuery query);
}

interface DeliveryResultRecorder {
    void recordDeliveryResult(DeliveryResultCommand command);
}
```

`DeliveryResultRecorder` 属于后续扩展接口，空骨架可以定义但不提供生产行为。

### 14.6 Operations API

```java
interface OperationsService {
    DashboardSummary getDashboard(OperationsQuery query, ActorContext actor);
```

Operations 的实现只编排已有模块 API，不自己访问其他模块的 Repository。

### 15.1 产品 DTO

```java
record ProductSummary(
```

```java
record ProductModePolicy(
```


```text

modePolicies

createdAt

```

### 15.2 文件资产 DTO

AssetIndex 内部领域对象应包含：

```java
record DataAsset(
    AssetId id,
    AssetType assetType,
    DataMode dataMode,
    Instant cycleTime,           // 实况为空
    Instant validTime,
    Integer leadMinutes,         // 实况为空
    String storageKey,
    String relativePath,
    String fileName,
    long fileSize,
    String checksum,             // 可空
    Integer dpi,                 // NETCDF为空
    Instant fileModifiedAt,
    AssetStatus status,
    Instant indexedAt
) {}
```

```text

```

时间约束：

```text

FORECAST：cycleTime和leadMinutes非空
FORECAST：validTime = cycleTime + leadMinutes
```

`storageKey` 标识配置中的逻辑存储空间，如 `webp-preview` 或 `netcdf-science`。数据库保存相对路径，不保存机器相关的绝对根路径。


### 15.4 身份 DTO

```java
record AuthenticatedUser(
    UserId id,
    String email,
    String organization,
    UserRole role
) {}
```

```text
UserStatus：ACTIVE / DISABLED
```

注册和登录 Command 不得进入日志；`password` 不得出现在任何输出 DTO 中。

### 15.5 下载 DTO

```java
record DownloadCommand(
    AssetId assetId,
    String purpose
) {}
```

```java
record DownloadGrant(
    DownloadEventId eventId,
    String downloadFileName,
    String contentType,
    long expectedBytes,
    String internalLocation
) {}
```

`internalLocation` 是应用层交给 Nginx 适配器的内部信息，HTTP JSON 响应不得直接暴露。

```text
DownloadStatus：REQUESTED / AUTHORIZED / DENIED / DELIVERED / INTERRUPTED
```

第一版业务只写入 `AUTHORIZED` 或 `DENIED`；`DELIVERED/INTERRUPTED` 为后续 Nginx 日志回写预留。

### 15.6 扫描 DTO

```java
record AssetScanResult(
    ScanTrigger trigger,
    Instant startedAt,
    Instant finishedAt,
    long scannedFiles,
    long createdAssets,
    long updatedAssets,
    long removedWebpAssets,
    long missingNetcdfAssets,
    Set<ProductCode> affectedProducts,
    List<AssetScanError> errors
) {}
```

```text
ScanTrigger：STARTUP / SCHEDULED / MANUAL
```

扫描错误必须包含安全的相对路径和错误代码，不返回生产绝对路径和异常堆栈给前端。

### 15.7 空值规则

- 跨模块查询未找到单个对象时使用 `Optional<T>`；
- 集合查询没有结果时返回空集合，不返回 `null`；
- Command 必填字段不得为空；
- `cycleTime/leadMinutes` 只允许在实况模式为空；
- DTO 中明确标注可空字段；
- 禁止使用 `Optional` 作为 record 字段或数据库实体字段；
- 空值组合必须在构造或应用服务入口校验。

## 16. 异常与错误契约

### 16.1 业务接口规则

业务接口使用明确的业务异常，不使用通用 `RuntimeException` 表达可预期业务失败，也不在每层包装 `Result<T>`。

基础异常结构：

```text
BusinessException
├─ errorCode
├─ safeMessage
└─ details（可选且必须脱敏）
```

建议错误代码和 HTTP 映射：

| 场景 | 错误代码 | HTTP |
| --- | --- | ---: |
| 参数格式或业务校验失败 | `VALIDATION_FAILED` | 422 |
| 未登录 | `UNAUTHENTICATED` | 401 |
| 无权限 | `FORBIDDEN` | 403 |
| 产品或资产不存在 | `NOT_FOUND` | 404 |
| 已知资产文件已丢失 | `ASSET_GONE` | 410 |
| 邮箱、产品编码等冲突 | `CONFLICT` | 409 |
| 登录或接口请求超限 | `RATE_LIMITED` | 429 |
| 外部 AI 服务暂时不可用 | `AI_UNAVAILABLE` | 503，可降级 |
| 未预期系统异常 | `INTERNAL_ERROR` | 500 |

### 16.2 HTTP 错误响应

HTTP 接入层统一转换业务异常，响应采用稳定的问题详情结构：

```json
{
  "code": "ASSET_GONE",
  "message": "该科学数据文件当前不可用",
  "traceId": "..."
}
```

禁止向客户端返回：

- Java 堆栈；
- SQL；
- 数据库表名；
- 生产绝对路径；
- Redis、Nginx 或模型凭据。

Redis 缓存不可用时不应直接产生业务错误，应记录监控并降级查询 MySQL。

## 17. ArchUnit 架构约束

空骨架必须包含架构测试，至少验证：

### 17.1 禁止循环依赖

七个业务模块之间不得形成依赖环。

### 17.2 跨模块只能访问 API

任何模块访问另一个业务模块时，只能引用目标模块的 `..api..` 包。

### 17.3 Domain 保持纯净

`..domain..` 不得依赖：

```text
Spring MVC
Spring Data
MyBatis
Redis
Nginx适配
具体AI SDK
```

### 17.4 接入层不能访问内部实现

`..interfaces..` 只能依赖各模块 `api` 和 `shared.kernel`，不得依赖业务模块的 `application/domain/infrastructure`。

### 17.5 Infrastructure 不能被跨模块依赖

任何业务模块不得引用其他模块的 `infrastructure`。

### 17.6 允许的业务依赖矩阵

```text
Catalog      → Shared
Identity     → Shared
AssetIndex   → Catalog API + Shared
Discovery    → Catalog API + AssetIndex API + Shared
Download     → AssetIndex API + Shared
Copilot      → Catalog API + Discovery API + Shared
Operations   → Catalog API + AssetIndex API + Discovery API
               + Identity API + Download API + Shared
```

依赖矩阵发生变化时，必须先更新架构文档并说明原因，再修改 ArchUnit 规则。

## 18. 空骨架 Mock 串联方式

空骨架阶段不连接 MySQL、Redis 或真实文件系统。

提供 `skeleton` Spring Profile，使用少量 Mock/Stub 实现：

```text
MockCatalog
MockAssetIndex
MockDiscovery
MockIdentity
MockDownload
MockOperations
MockCopilot
```

Mock 数据只用于证明模块能够串联，不代表真实实现。建议至少包含：

```text
产品：BT855、PRECIP、PLP
一个BT855 WebP预览帧
一个包含PLP/PRECIP的NC摘要
一个普通用户
一个管理员
一个AUTHORIZED下载审计
```

需要串通的主流程：

```text
普通用户：
产品目录
→ WebP预览查询
→ 注册/登录
→ NC历史检索
→ 下载授权

管理员：
登录
→ 仪表盘
→ 产品草稿/发布
→ 手动扫描
→ 下载审计

Copilot：
自然语言
→ 结构化查询
→ Discovery Mock结果
```

Mock 不得生成假性能数据，不得以 Mock 成功代替后续真实集成测试。

## 20. 空骨架验收标准

代码即架构的空骨架完成时，必须满足：

- [ ] Maven Wrapper 可以在未安装全局 Maven 的环境运行；
- [ ] Java 17 编译通过；
- [ ] Spring Boot 使用 `skeleton` Profile 可以启动；
- [ ] 七个业务模块的目录、公开接口和核心 DTO 已建立；
- [ ] 模块实现只通过公开 API 协作；
- [ ] 两条用户故事可以通过 Mock 串联；
- [ ] Copilot 只能调用 Catalog 和 Discovery；
- [ ] Controller/LegacyAdapter 不包含业务逻辑；
- [ ] ArchUnit 规则全部通过；
- [ ] 单元和上下文测试通过；
- [ ] 不连接生产服务器；
- [ ] 不连接真实 MySQL、Redis 和文件系统；
- [ ] 不包含 NC、HDF、WebP、凭据和生产配置；
- [ ] README 说明如何运行构建和测试；
- [ ] 没有虚构已实现功能或性能数字。

空骨架完成不代表业务已经实现。它只代表模块边界、接口、数据结构和主干调用已经通过真实代码固定下来。
