# 大禹系统数据库旧设计继承与新模型映射

> 文档状态：逐表评审完成，首版 DDL 已通过临时 MariaDB 10.6 验证
> 整理日期：2026-10-01
> 适用范围：大禹平台 Java 重构的 MySQL/MariaDB 业务库
> 本文目的：明确旧库哪些设计继续使用、哪些字段需要调整、为什么新增文件索引表，以及索引如何对应真实查询。本文确认后再编写数据库迁移，不以本文代替可执行 DDL。

---

## 1. 调查依据与边界

旧系统实际使用以下五张业务表：

```text
users
products
product_admin_events
login_attempts
download_events
```

旧系统没有文件元数据索引表。产品目录来自数据库，但 WebP、NC 的列表和时间信息由 PHP 在请求期间扫描目录并解析文件名获得。

本次设计遵守以下已确认边界：

- 科学栅格文件继续存放在硬盘或挂载文件系统，不写入数据库；
- 硬盘是文件是否真实存在的最终依据；
- `data_assets` 是可以通过重新扫描恢复的查询索引；
- WebP 与 NC 不要求一一对应；
- 一个文件可以关联多个产品；
- 数据库和后端时间统一使用 UTC；
- 第一版不解析 NC 内部变量供用户查询；
- 前端下载时提交 `assetId`，不再提交服务器文件路径。

旧系统证据来源：

- `database/schema.sql`：五张旧表及约束；
- `api/product_catalog.php`：产品目录查询；
- `api/files.php`、`api/search.php`、`api/fcst_latest.php`：目录扫描和文件名解析；
- `api/auth.php`：用户与登录尝试；
- `api/download.php`：下载审计与文件传输；
- `api/admin.php`、`api/admin_products.php`：产品管理、统计和审计。

## 2. 总体继承结论

| 旧表/能力 | 新方案 | 结论 |
| --- | --- | --- |
| `users` | `users` | 保留核心字段和业务含义 |
| `products` | `products` + `product_mode_policies` | 保留产品目录，拆出实况/预报策略 |
| `product_admin_events` | `product_admin_events` | 保留产品变更审计 |
| `login_attempts` | `login_attempts` | 保留登录限流依据，补强索引 |
| `download_events` | `download_events` + `download_event_products` | 保留用途和审计，改为关联 `asset_id` 并保存事件快照 |
| 请求时扫描目录 | `data_assets` + `data_asset_products` | 新增可重建文件索引，替代高频请求临时扫描 |
| 管理页面临时扫描统计 | `asset_scan_runs` + `asset_scan_errors` | 新增持久化扫描历史和安全错误摘要 |
| PHP Session | Spring Security Session | 不放入上述业务表；第一版由单实例 Session 管理，未来可迁移到 Redis |

目标关系：

```text
products 1 ── N product_mode_policies
products N ── N data_assets              （经 data_asset_products）
users    1 ── N download_events
download_events 1 ── N download_event_products
products 1 ── N product_admin_events
users    1 ── N product_admin_events      （管理员）
users    1 ── N asset_scan_runs           （仅手动扫描）
asset_scan_runs 1 ── N asset_scan_errors
```

## 3. 通用物理设计约定

| 项目 | 新库约定 | 原因 |
| --- | --- | --- |
| 表名和列名 | 小写 `snake_case` | 与现有数据库一致，SQL 清晰 |
| 主键 | `BIGINT` 自增 | 与 Java `long`/ID 值对象直接对应 |
| 时间 | `DATETIME(6)`，应用只写 UTC | 避免时区歧义，保留微秒，范围不受 `TIMESTAMP` 2038 限制 |
| 状态和类型 | `VARCHAR(32)` + 应用枚举 + 数据库检查约束 | 比数据库 `ENUM` 更便于增加状态和跨数据库测试 |
| 字符集 | `utf8mb4` | 支持中英文及完整 Unicode |
| 引擎 | InnoDB | 支持事务、行锁和外键 |
| 大文件内容 | 不入库 | WebP/NC 继续由文件系统保存 |
| 绝对路径 | 不入库 | 只保存逻辑存储空间和相对路径，部署环境提供真实根目录 |

所有业务时间字段的含义必须写在列注释和 Java 文档中。数据库连接时区必须配置为 UTC；前端展示时区不进入这些字段。

## 4. `users`：基本继承

### 4.1 旧字段到新字段

| 旧字段 | 新字段 | 处理 | 说明 |
| --- | --- | --- | --- |
| `id` | `id BIGINT` | 保留 | 用户内部主键，对应 `UserId` |
| `email` | `email VARCHAR(254)` | 保留 | 注册和登录标识；写入前转小写并去除首尾空格 |
| `password_hash` | `password_hash VARCHAR(255)` | 保留 | 只保存安全哈希，不保存明文密码 |
| `organization` | `organization VARCHAR(255)` | 保留 | 用户所属单位 |
| `role` | `role VARCHAR(32)` | 保留含义、调整类型 | `USER` / `ADMIN` |
| `status` | `status VARCHAR(32)` | 保留含义、调整类型 | `ACTIVE` / `DISABLED` |
| `created_at` | `created_at DATETIME(6)` | 保留 | UTC 创建时间 |
| `updated_at` | `updated_at DATETIME(6)` | 保留 | UTC 最后修改时间 |

### 4.2 约束和索引

| 名称 | 列 | 用途 |
| --- | --- | --- |
| `pk_users` | `id` | 主键 |
| `uq_users_email` | `email` | 防止同一邮箱重复注册，并支持登录查询 |
| `idx_users_role_status_id` | `role, status, id` | 管理员按角色和状态分页查询用户 |

旧索引 `idx_users_status` 与 `idx_users_role_status` 功能重叠。新库只保留能够覆盖实际管理查询的联合索引，避免无依据地堆索引。

## 5. `products`：继承目录，移除实况/预报重复产品

### 5.1 关键模型变化

旧库把实况和预报存成两行产品：

```text
BT855       category = realtime
FCST_BT855  category = forecast
```

新模型只保留一个产品：

```text
products.code = BT855
product_mode_policies = REALTIME、FORECAST
```

因此 `REALTIME/FORECAST` 是数据模式，不再是产品身份的一部分。

### 5.2 旧字段到新字段

| 旧字段 | 新字段或去向 | 处理 | 说明 |
| --- | --- | --- | --- |
| `id` | `id BIGINT` | 保留 | 对应 `ProductId` |
| `product_id` | `code VARCHAR(64)` | 重命名并归一化 | 去掉旧预报行的 `FCST_` 前缀；如 `FCST_BT855 → BT855` |
| `path_id` | 不作为核心产品字段 | 废弃存储 | 旧 Legacy 路径标识通常可由产品编码推导；兼容层负责转换 |
| `category` | `product_mode_policies.data_mode` | 移出产品表 | 产品是否支持实况/预报由模式策略表达 |
| `name_zh` | `name_zh VARCHAR(255)` | 保留 | 中文名称 |
| `name_en` | `name_en VARCHAR(255)` | 保留 | 英文名称 |
| `title_zh` | 不单独存储 | 废弃 | 页面标题由数据模式和名称组合，避免重复事实 |
| `title_en` | 不单独存储 | 废弃 | 同上 |
| `stale_after_minutes` | `product_mode_policies.stale_after_minutes` | 移出产品表 | 实况和预报可配置不同过期阈值 |
| `sort_order` | `sort_order INT` | 保留 | 产品展示顺序 |
| `colorbar_required` | `colorbar_required BOOLEAN` | 保留 | 是否必须配置色标 |
| 无 | `colorbar_path VARCHAR(512) NULL` | 新增 | 保存逻辑相对路径，不保存机器绝对路径 |
| 无 | `family VARCHAR(64)` | 新增 | 文件族/产品族，如 `BT`、`CPP`、`REPPIC_PRECIP` |
| 无 | `unit VARCHAR(64) NULL` | 新增 | 用户展示用单位；RGB/FRGB 等可为空 |
| 无 | `description_zh TEXT` | 新增 | 中文产品说明 |
| 无 | `description_en TEXT` | 新增 | 英文产品说明 |
| 无 | `producer VARCHAR(255)` | 新增 | 产品生产者，如课题组 |
| 无 | `algorithm_name VARCHAR(255) NULL` | 新增 | 算法名称，如 RePPIC-Net |
| 无 | `source_description TEXT` | 新增 | 上游来源简述 |
| 无 | `official_source_url VARCHAR(1024) NULL` | 新增 | FY-4B 官方数据入口，不代理原始 HDF 下载 |
| `status` | `status VARCHAR(32)` | 保留含义、规范名称 | `draft → DRAFT`、`active → PUBLISHED`、`disabled → DISABLED` |
| `created_by` | `created_by BIGINT NULL` | 保留 | 创建管理员；删除用户时置空 |
| `updated_by` | `updated_by BIGINT NULL` | 保留 | 最近修改管理员；删除用户时置空 |
| `published_at` | `published_at DATETIME(6) NULL` | 保留 | 首次发布时间 |
| `created_at` | `created_at DATETIME(6)` | 保留 | UTC |
| `updated_at` | `updated_at DATETIME(6)` | 保留 | UTC |

### 5.3 约束和索引

| 名称 | 列 | 用途 |
| --- | --- | --- |
| `pk_products` | `id` | 主键 |
| `uq_products_code` | `code` | 产品编码唯一 |
| `idx_products_status_sort_id` | `status, sort_order, id` | 公开产品目录：只查 `PUBLISHED` 并排序 |
| `idx_products_family_status_id` | `family, status, id` | 管理员按产品族和状态查询 |

产品生命周期采用可停用、可重新发布的状态机：

```text
DRAFT → PUBLISHED ↔ DISABLED
```

`DISABLED → PUBLISHED` 必须重新校验产品配置、必要色标和模式配置，并写入管理审计。`published_at` 保留第一次发布时间，重新发布时间由审计事件记录。

## 6. `product_mode_policies`：从旧 `products.category` 拆出

该表表示一个产品在哪些数据模式下启用，以及每种模式多久未更新算过期。

| 字段 | 建议类型 | 含义 |
| --- | --- | --- |
| `product_id` | `BIGINT` | 关联 `products.id` |
| `data_mode` | `VARCHAR(32)` | `REALTIME` / `FORECAST` |
| `enabled` | `BOOLEAN` | 当前是否启用该模式 |
| `stale_after_minutes` | `INT` | 数据过期阈值，必须为正数 |
| `created_at` | `DATETIME(6)` | UTC 创建时间 |
| `updated_at` | `DATETIME(6)` | UTC 修改时间 |

约束和索引：

| 名称 | 列 | 用途 |
| --- | --- | --- |
| `pk_product_mode_policies` | `product_id, data_mode` | 一个产品每种模式最多一条策略 |
| `idx_product_modes_enabled_mode` | `enabled, data_mode, product_id` | 查询某模式下启用的产品 |

删除产品时不物理删除产品历史，正常业务通过状态停用；外键使用 `ON DELETE RESTRICT`。

## 7. `data_assets`：新增真实文件索引

一行表示硬盘上的一个真实物理文件。它是查询索引，不保存文件内容。

### 7.1 字段

| 字段 | 建议类型 | 含义与约束 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键，对应 `assetId` |
| `storage_key` | `VARCHAR(32)` | 逻辑存储空间，如 `webp-preview`、`netcdf-data` |
| `relative_path` | `VARCHAR(700)` | 相对该存储空间根目录的路径；禁止绝对路径和路径逃逸；长度为完整联合唯一索引预留空间 |
| `file_name` | `VARCHAR(512)` | 安全展示和下载文件名 |
| `asset_type` | `VARCHAR(32)` | `WEBP` / `NETCDF` |
| `data_mode` | `VARCHAR(32)` | `REALTIME` / `FORECAST` |
| `cycle_time` | `DATETIME(6) NULL` | 预报起报时间；实况必须为空 |
| `valid_time` | `DATETIME(6)` | 数据有效时间 |
| `lead_minutes` | `INT NULL` | 预报时效；实况必须为空 |
| `file_size` | `BIGINT` | 文件字节数，必须非负 |
| `checksum_sha256` | `CHAR(64) NULL` | 可选校验和；第一版不要求每次扫描都计算 |
| `dpi` | `INT NULL` | WebP 可用；NC 为空 |
| `file_modified_at` | `DATETIME(6)` | 文件系统修改时间 |
| `indexed_at` | `DATETIME(6)` | 最近一次更新索引的时间 |
| `last_seen_at` | `DATETIME(6)` | 最近一次扫描确认文件存在的时间 |
| `status` | `VARCHAR(32)` | `AVAILABLE` / `MISSING` |

领域约束：

```text
REALTIME：cycle_time = null，lead_minutes = null
FORECAST：cycle_time != null，lead_minutes != null
FORECAST：valid_time = cycle_time + lead_minutes
WEBP：dpi 可以有值
NETCDF：dpi 必须为空
```

### 7.2 索引

| 名称 | 列 | 对应查询场景 |
| --- | --- | --- |
| `pk_data_assets` | `id` | 按 `assetId` 下载授权 |
| `uq_data_assets_storage_path` | `storage_key, relative_path` | 重复扫描幂等，不产生重复资产 |
| `idx_assets_timeline` | `asset_type, data_mode, status, valid_time, id` | WebP 时间轴和历史 NC 时间范围查询 |
| `idx_assets_forecast_cycle` | `asset_type, data_mode, status, cycle_time, valid_time, id` | 查询某个预报批次及其有效时次 |
| `idx_assets_status_last_seen` | `status, last_seen_at, id` | 扫描后识别缺失文件和清理索引 |

`storage_key` 和 `relative_path` 使用 `utf8mb4` 时，完整联合索引最坏约占
`(32 + 700) × 4 = 2928` 字节，低于常见 InnoDB 3072 字节索引键上限。
因此不需要使用可能产生“前缀相同但完整路径不同”问题的前缀唯一索引，也暂不引入额外的路径哈希列。

这里不建立 WebP→NC 外键。近期预览页面需要寻找可下载 NC 时，根据产品、数据模式和时间动态查询。

## 8. `data_asset_products`：新增文件与产品多对多映射

该表回答“这个物理文件包含或对应哪些产品”。

| 字段 | 建议类型 | 含义 |
| --- | --- | --- |
| `asset_id` | `BIGINT` | 关联 `data_assets.id` |
| `product_id` | `BIGINT` | 关联 `products.id` |

约束和索引：

| 名称 | 列 | 用途 |
| --- | --- | --- |
| `pk_data_asset_products` | `asset_id, product_id` | 防止同一映射重复，并支持从资产查询全部产品 |
| `idx_data_asset_products_product_asset` | `product_id, asset_id` | 从产品查询资产 |

示例：

```text
一张 BT855 WebP
└─ BT855

一个 BT NetCDF
├─ BT625
├─ BT695
├─ BT742
├─ BT855
├─ BT108
├─ BT120
└─ BT133

一个 RePPIC NetCDF
├─ PLP
└─ PRECIP
```

删除可重建的资产索引时，映射可 `ON DELETE CASCADE`；产品不物理删除，产品外键使用 `ON DELETE RESTRICT`。

## 9. `login_attempts`：继承并补强实际限流索引

### 9.1 旧字段到新字段

| 旧字段 | 新字段 | 处理 |
| --- | --- | --- |
| `id` | `id BIGINT` | 保留 |
| `email` | `email VARCHAR(254)` | 保留；即使用户不存在也要记录 |
| `ip_address` | `ip_address VARCHAR(45)` | 保留；兼容 IPv4/IPv6 文本 |
| `successful` | `successful BOOLEAN` | 保留 |
| `attempted_at` | `attempted_at DATETIME(6)` | 保留，UTC |

### 9.2 索引

旧登录逻辑分别需要判断“某邮箱”或“某 IP”最近一段时间的失败次数。新库保留两条独立索引：

| 名称 | 列 |
| --- | --- |
| `idx_login_attempts_email_result_time` | `email, successful, attempted_at` |
| `idx_login_attempts_ip_result_time` | `ip_address, successful, attempted_at` |
| `idx_login_attempts_time` | `attempted_at` |

第三条索引用于定期删除超过保留期的限流记录。保留期限由配置决定，不硬编码在表结构中。

## 10. `download_events`：继承下载审计，改用资产 ID 和快照

### 10.1 旧字段到新字段

| 旧字段 | 新字段或去向 | 处理 | 原因 |
| --- | --- | --- | --- |
| `id` | `id BIGINT` | 保留 | 对应 `DownloadEventId` |
| `user_id` | `user_id BIGINT` | 保留 | 发起下载的用户 |
| 无 | `organization_snapshot VARCHAR(255)` | 新增 | 单位以后变化时，历史审计仍保持原状 |
| `file_path` | `asset_id BIGINT` | 替换 | 前端和审计不再依赖服务器路径 |
| 无 | `file_name_snapshot VARCHAR(512)` | 新增 | 资产信息以后变化时仍能解释历史事件 |
| 无 | `expected_bytes BIGINT` | 新增 | 授权时文件大小快照 |
| `purpose` | `purpose TEXT` | 保留 | 使用意图，长度规则继续由业务校验 |
| `ip_address` | `ip_address VARCHAR(45)` | 保留 | 安全和审计信息 |
| `user_agent` | `user_agent VARCHAR(500)` | 保留 | 安全和审计信息 |
| `status` | `status VARCHAR(32)` | 扩展语义 | `REQUESTED/AUTHORIZED/DENIED/DELIVERED/INTERRUPTED` |
| 无 | `denial_reason_code VARCHAR(64) NULL` | 新增 | 记录安全的拒绝原因编码，不记录敏感异常 |
| `requested_at` | `requested_at DATETIME(6)` | 保留 | 用户提出请求时间 |
| 无 | `authorized_at DATETIME(6) NULL` | 新增 | Java 完成授权的时间 |
| `completed_at` | `finished_at DATETIME(6) NULL` | 重命名并收紧语义 | 仅在取得传输完成/中断证据时填写 |
| 无 | `delivered_bytes BIGINT NULL` | 新增 | 未来由 Nginx 日志回写传输字节数 |

第一版主要写入 `AUTHORIZED` 或 `DENIED`。不能把“Java 已授权”描述成“用户已完整保存文件”。

### 10.2 索引

| 名称 | 列 | 对应查询 |
| --- | --- | --- |
| `pk_download_events` | `id` | 主键和后续传输结果回写 |
| `idx_download_events_time_id` | `requested_at, id` | 不附加其他条件时，按时间范围稳定分页 |
| `idx_download_events_status_time_id` | `status, requested_at, id` | 管理员按状态和时间分页、统计 |
| `idx_download_events_user_time_id` | `user_id, requested_at, id` | 按用户查询下载审计 |
| `idx_download_events_asset_time_id` | `asset_id, requested_at, id` | 查看某资产的下载记录 |
| `idx_download_events_org_time_id` | `organization_snapshot, requested_at, id` | 按单位筛选和统计 |

`user_id` 和 `asset_id` 使用 `ON DELETE RESTRICT`。用户和长期 NC 资产通过状态停用或标记缺失，不因日常操作删除审计依据。

## 11. `download_event_products`：新增下载时产品快照

一个 NC 可以关联多个产品，管理员又需要按产品筛选历史下载。不能继续像旧系统一样从文件路径猜产品，也不应依赖产品当前名称。

| 字段 | 建议类型 | 含义 |
| --- | --- | --- |
| `download_event_id` | `BIGINT` | 关联 `download_events.id` |
| `product_code_snapshot` | `VARCHAR(64)` | 下载发生时的产品编码快照 |

约束和索引：

| 名称 | 列 | 用途 |
| --- | --- | --- |
| `pk_download_event_products` | `download_event_id, product_code_snapshot` | 防止快照重复 |
| `idx_download_event_products_code_event` | `product_code_snapshot, download_event_id` | 管理员按产品查询下载审计 |

这里有意保存产品编码快照，而不是只保存 `product_id` 外键。这样产品停用、改名或未来归档后，历史审计仍能独立解释。

## 13. `asset_scan_runs` 与 `asset_scan_errors`：新增扫描历史

旧管理接口只在请求期间扫描目录并临时统计。新系统需要持久化每次定时或手动扫描的结果，管理员才能判断索引是否正常更新。

### 13.1 `asset_scan_runs`

| 字段 | 建议类型 | 含义 |
| --- | --- | --- |
| `id` | `BIGINT` | 扫描批次主键 |
| `trigger_type` | `VARCHAR(32)` | `STARTUP` / `SCHEDULED` / `MANUAL`，与 `ScanTrigger` 一致 |
| `triggered_by_user_id` | `BIGINT NULL` | 手动扫描的管理员；启动和定时扫描为空 |
| `status` | `VARCHAR(32)` | `RUNNING` / `SUCCEEDED` / `PARTIAL` / `FAILED` |
| `started_at` | `DATETIME(6)` | UTC 开始时间 |
| `finished_at` | `DATETIME(6) NULL` | UTC 结束时间 |
| `scanned_files` | `BIGINT` | 扫描文件数 |
| `created_assets` | `BIGINT` | 新增资产数 |
| `updated_assets` | `BIGINT` | 更新资产数 |
| `removed_webp_assets` | `BIGINT` | 已清理 WebP 索引数 |
| `missing_netcdf_assets` | `BIGINT` | 标记为缺失的 NC 数 |
| `error_count` | `INT` | 安全错误摘要数量 |

索引：

```text
PRIMARY KEY (id)
INDEX idx_asset_scan_runs_started_id (started_at, id)
INDEX idx_asset_scan_runs_trigger_started_id (trigger_type, started_at, id)
INDEX idx_asset_scan_runs_user_started_id (triggered_by_user_id, started_at, id)
```

`triggered_by_user_id` 关联 `users.id`。账号正常只禁用、不物理删除；如未来执行受控匿名化，扫描记录可以保留并将该字段置空。

### 13.2 `asset_scan_errors`

| 字段 | 建议类型 | 含义 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 |
| `scan_run_id` | `BIGINT` | 关联扫描批次 |
| `relative_path` | `VARCHAR(1024)` | 相对路径，不记录生产绝对路径 |
| `error_code` | `VARCHAR(64)` | 可统计的安全错误码 |
| `safe_message` | `VARCHAR(1000)` | 脱敏说明，不保存堆栈或凭据 |
| `created_at` | `DATETIME(6)` | UTC |

索引：

```text
PRIMARY KEY (id)
INDEX idx_asset_scan_errors_run_id (scan_run_id, id)
```

扫描批次删除时错误明细可以 `ON DELETE CASCADE`。正常业务默认按保留期清理历史扫描记录，不影响 `data_assets`。

## 14. 全局外键与删除规则

| 关联关系 | 外键删除规则 | 设计原因 |
| --- | --- | --- |
| `product_mode_policies.product_id → products.id` | `RESTRICT` | 防止意外物理删除仍有模式配置的产品 |
| `data_asset_products.product_id → products.id` | `RESTRICT` | 保留产品与历史文件的关系 |
| `data_asset_products.asset_id → data_assets.id` | `CASCADE` | 资产索引删除后，其产品标签关系不再有意义 |
| `download_events.user_id → users.id` | `RESTRICT` | 下载审计必须保留责任用户 |
| `download_events.asset_id → data_assets.id` | `RESTRICT` | 有下载审计的 NC 资产不得物理删除 |
| `download_event_products.download_event_id → download_events.id` | `CASCADE` | 产品快照只属于该下载事件 |
| `product_admin_events.product_id → products.id` | `RESTRICT` | 有管理历史时不得删除产品 |
| `product_admin_events.admin_user_id → users.id` | `SET NULL` | 允许受控匿名化，同时保留管理事件 |
| `asset_scan_runs.triggered_by_user_id → users.id` | `SET NULL` | 允许受控匿名化，同时保留扫描历史 |
| `asset_scan_errors.scan_run_id → asset_scan_runs.id` | `CASCADE` | 清理过期扫描批次时同步清理错误明细 |

核心业务数据默认使用状态变化代替物理删除：

```text
用户停止使用 → DISABLED
产品停止提供 → DISABLED
NC 文件消失 → MISSING
```

允许按策略物理清理的主要是可重建数据：已过期的 WebP 资产索引，以及超过保留期的扫描历史和错误明细。

| 内容 | 存放位置 |
| --- | --- |

## 16. 旧数据迁移规则

### 15.1 产品合并

旧产品行按去除 `FCST_` 后的编码合并：

```text
BT855 + FCST_BT855 → products.BT855
                        ├─ REALTIME policy
                        └─ FORECAST policy
```

如果两行中英文名称不一致，迁移不能静默任选，必须输出冲突报告人工确认。

### 15.2 用户

- 保留旧用户 ID、邮箱、密码哈希、单位、角色和状态；
- 迁移前检查邮箱大小写归一化后是否冲突；
- 不在迁移日志中输出密码哈希和真实用户资料。

### 15.3 下载事件

旧事件只有 `file_path`，没有 `asset_id`。迁移时先建立文件索引，再尝试通过规范化相对路径匹配资产：

```text
唯一匹配 → 写入 asset_id 和文件快照
无法匹配/多个匹配 → 进入迁移异常报告，不凭文件名猜测
```

旧状态建议映射：

```text
started   → REQUESTED
completed → DELIVERED（只表示旧 PHP 传输循环完成，不表示用户已保存）
```

是否将生产历史数据迁入新环境，应在部署阶段单独确认；本地开发数据库使用匿名测试数据。

### 15.4 文件索引

`data_assets` 和 `data_asset_products` 不从旧数据库迁移，因为旧库没有这些事实。它们通过扫描真实文件重新建立。

| 业务动作 | 主要表 | 使用的关键索引 |
| --- | --- | --- |
| 查询已发布产品目录 | `products` | `status, sort_order, id` |

| 登录查用户 | `users` | 唯一索引 `email` |

## 18. 与旧接口的兼容边界

Legacy API 可以继续返回旧字段和旧 JSON 结构，但只能作为转换层：

```text
旧 URL/参数
→ Legacy Controller
→ 调用新的 Application API
→ 把新 DTO 转成旧 JSON
```

Legacy 层不得：

- 重新直接扫描目录；
- 直接访问数据库表；
- 根据文件路径自行实现产品判断；
- 绕过新的身份、下载用途和路径安全校验。

旧 `path_id`、`category`、`title_zh/title_en` 如果仍需出现在旧响应中，由兼容层根据 `code`、`dataMode` 和名称生成，不要求继续作为新数据库的重复事实保存。

## 19. 定稿前需要确认的非结构性事项

以下事项不改变主要表关系，但在编写迁移和保留策略前需要确认：

1. 新环境是否迁移生产用户和历史下载审计，还是只在最终切换时迁移；
2. `login_attempts`、`asset_scan_runs` 和扫描错误分别保留多久；
3. 旧 `completed` 下载记录迁移为 `DELIVERED` 时，管理页面是否明确标注“服务端传输完成”；
4. Legacy API 是否确实仍要求返回 `path_id` 和旧标题字段，待 HTTP 契约调查时逐接口确认。

这些问题不阻塞下一步编写数据库 DDL 初稿和 `/api/v1` 契约，但在生产迁移前必须解决。
