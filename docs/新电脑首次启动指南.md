# 新电脑首次启动指南（Windows）

目标：从源码构建并启动独立开发数据库和真实后端，初始化管理员、产品与模式。不启动前端、不扫描科学文件，也不执行全量测试。模型是否启用由 `.env` 开关决定，启动本身不调用模型。

## 1. 安装与克隆

准备 Git、JDK 17、Docker Desktop（包含 Docker Compose 2.22 或更新版本），并启动 Docker 引擎。首次使用需要联网下载 Maven、Java 依赖和 MariaDB 镜像；无需另外安装 Maven 或 MariaDB。

请从 `main` 获取合并后的稳定后端和启动脚本。开发任务分支在合并后会清理，不应作为长期的克隆入口。不要把旧电脑的 `target/`、`.env*` 实际配置或 Docker 数据卷当成初始化前提。

```powershell
git clone --branch main https://github.com/jyqin0203/dayu-platform.git
cd dayu-platform
```

私有仓库需要你自己的 GitHub 访问权限，凭据不要放进命令或仓库。

检查 `JAVA_HOME` 指向 JDK 17，而不是旧的 Java 8。若需要临时指定，在当前 PowerShell 中设置（替换为你电脑的实际路径）：

```powershell
$env:JAVA_HOME='C:\你的JDK17安装目录'
```

脚本会校验 JDK，不修改系统级环境变量。当前提供并验证的是 Windows PowerShell 流程，不宣称已支持 Linux/macOS 启停脚本。

## 2. 生成本地配置

```powershell
.\scripts\setup-local.ps1
```

| 仓库中的模板 | 本地使用的文件 | 作用 |
| --- | --- | --- |
| `.env.local.example` | `.env.local` | 开发实例名、数据库/HTTP 端口 |
| `.env.local-db.example` | `.env.local-db` | MariaDB 应用用户密码 |
| `.env.local-admin.example` | `.env.local-admin` | 本地管理员账号密码 |
| `.env.example` | `.env` | Qwen 密钥、模型和开关，默认关闭 |

推荐直接运行 setup：缺失的开发密码会独立随机生成，只写本地文件，不输出内容。也可以在新电脑手动复制模板、填写密码，再运行 setup 检查。模板中的密码故意留空，不能直接作为可用凭据。

本地启动配置采用简单的 `KEY=VALUE` 格式，不执行 shell 代码；请不要给密码添加引号或行尾注释，管理员邮箱保留模板中的专用本地账号。

**已有文件不会被覆盖。** 已有数据库卷却丢失密码文件时，脚本拒绝生成新密码，以免误以为“改文件就能重置数据库”。实例或端口与已有配置冲突时也会拒绝静默切换。

默认数据库 `127.0.0.1:13306/dayu`、用户 `dayu`；后端 `127.0.0.1:18080`。需要其他端口时，在第一次 setup 指定：

```powershell
.\scripts\setup-local.ps1 -InstanceName dayu-alternate -DatabasePort 13406 -BackendPort 18480
```

不同实例使用独立容器/数据卷。已建库后不要随便改实例名，原数据不会自动迁移到新实例。

## 3. 构建与启动

```powershell
.\scripts\build-local.ps1
.\scripts\start-local.ps1
```

build 使用仓库 Maven wrapper 执行 `-DskipTests package`：编译、打包，但**没有运行测试**。构建失败时停止，不应继续使用旧 JAR。

start 只启动这个实例的 MariaDB 和后台 Java 进程：

- 等待 MariaDB 健康后再启动后端；
- Flyway 自动执行 V1～V4，生成 11 张业务表和 1 张迁移历史表；
- 只监听 `127.0.0.1`，数据库密码通过进程环境传递，不放在命令行；
- 固定关闭自动扫描和 Redis；读取 `.env.local` 的数据目录及 `.env` 中的 Qwen 白名单配置；可用 `-DisableCopilot` 强制关闭模型；
- 日志放在 `logs/`，进程标识放在 `tmp/local-backend.json`，均不提交 Git；
- HTTP 端口被占用时不杀其他进程。

打开 <http://127.0.0.1:18080/api/v1/products>。首次建库返回 `[]` 正常；如果修改了端口，使用你配置的 HTTP 端口。首次启动可能较慢，脚本最多等待后端 180 秒。

## 4. 首次初始化管理员与产品

```powershell
.\scripts\initialize-local-products.ps1 -BootstrapAdmin
```

该参数只允许空用户库：注册本地开发账号、引导其成为管理员、重新登录，然后通过带 Session/CSRF 的管理员接口创建和发布产品。密码来自 `.env.local-admin`，不要粘贴到聊天中。

预期结果：17 个产品、29 条模式策略、15 个 PUBLISHED；PLP/PRECIP 因缺必要色标保持 DRAFT。CTH/CER/COT 的预报已包含在清单中，360 分钟是本地暂定新鲜度阈值。科学文件索引和扫描任务仍为空。

后续补充初始化可以不带 `-BootstrapAdmin` 运行；已有产品跳过，不覆盖你手动修改的资料或模式。脚本不承担中断后自动修复、旧生产数据迁移或已有账号密码重置。

## 5. 查看数据库、停止与再次启动

数据库管理工具中连接 `127.0.0.1:13306`，库 `dayu`、用户 `dayu`，密码取 `.env.local-db` 对应值。管理员账号是应用账号，不是数据库连接账号。

```sql
SHOW TABLES;
SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;
SELECT code, status FROM products ORDER BY sort_order;
```

```powershell
# 只停止此目录启动并记录的 Java 进程
.\scripts\stop-local.ps1

# 同时停止该实例数据库，但保留数据卷
.\scripts\stop-local.ps1 -Database

# 下次启动：不用重建配置或重新 bootstrap
.\scripts\start-local.ps1
```

停止脚本检查 PID、进程启动时间、JAR 路径和端口，防止 PID 被复用后杀错进程。旧脚本启动且没有进程记录的实例需要先由你确认 PID 手动停止，脚本不会按端口盲目终止进程。不要删除数据卷或执行 `down -v`。

代码修改后先停止旧后端，再 build、start。Flyway 自动应用新增迁移；不要修改已经执行过的迁移文件。

## 6. Git 带走什么

提交的是脚本、Compose、产品清单和 `.example` 模板。实际 `.env`、`.env.local*`、密码、日志、进程记录、JAR、数据库及科学文件都不提交。另一台电脑应生成自己的开发密码；需要同步真实数据库内容时另行设计导出/导入，不通过 Git 复制数据卷。
