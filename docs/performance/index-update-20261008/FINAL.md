完整无变化重扫中位数减少 **97.78%**，SQL 次数减少 **99.47%**。源目录指纹和业务状态指纹在六轮完全一致；新增、变化、移除、缺失和错误均为零。

## 最小改动及调用链

`PersistentAssetScanner` 仍完整遍历所有配置根目录；普通文件累计最多 200 条后交给 `AssetIndexStore.upsertBatch`。`JdbcAssetIndexStore` 在一个分块事务中：

1. 按存储空间和路径集合查询已有资产，再一次查关联产品。
2. 在内存对比状态、类型、模式、时间、时效、DPI、大小、微秒精度修改时间及产品关联。
3. 无变化的资产批量 UPDATE `last_seen_at`，避免逐文件查询、关联查询及提交。
4. 新增、变化、恢复的资产仍调用既有 `upsert`，复用约束、路径身份和关联更新规则；这些操作加入当前分块事务。

因此收益来自**批量读取、无变化记录批量标记及减少事务提交**，并非只加了一个内存 Map。新增/变化文件仍有逐条 SQL；没有宣称把所有写入都变成单条批量 INSERT。

批量失败整体回滚，扫描器再逐文件处理以保留成功文件进度和具体错误。任一文件最终失败，仍禁止该根缺失清理。正常分块成功后才计入新增/更新和受影响产品，避免回滚后重复计数。

RePPIC 不进入普通分块，沿用三时效原子发布/撤回，继续合并数据库已有周期，防止文件全部消失时漏检。未采用“只扫最新日期”或“目录 mtime 不变就跳过”，因此历史回补路径仍会访问。

没有新增表、索引、中间件或跨模块依赖。批量查询 EXPLAIN 使用原有 `uq_data_assets_storage_path`，`range`，200 条输入估计 200 行，见 `results/prefetch-explain.tsv`。新增索引缓冲最多 200 条，避免一次将历史资产全量读入内存。

## 环境、限制和资源

MariaDB 10.6.23；128 MiB buffer pool，`innodb_flush_log_at_trx_commit=1`，最多 10 连接，只监听私有 Unix socket。数据库固定 CPU 2，Java 固定 CPU 3，nice 15、idle I/O 优先级；Java 最大堆 256 MiB、ActiveProcessorCount=1。两版相同资源和持久性设置，不修改 fsync 制造收益。

固定元数据实验记录的 JVM 累计 VmHWM，A 最大 216,272 KiB，B 最大 201,828 KiB；包含 JVM、初始化、探针元数据和校验开销，**不把这个差值作为扫描器内存优化收益**。数据库观察到 VmHWM 272,088 KiB；buffer pool 不是数据库总内存。完整扫描 JVM VmHWM 最大 A 为 271,524 KiB、B 为 250,080 KiB，约 265.16 / 244.22 MiB，同样包含探针和 JVM 开销。堆/CPU 亲和性不是全进程内存/CPU 总量硬配额；本次未修改正式服务的 cgroup。

这是同一台共享服务器上的低优先级隔离实验，不是空闲独占硬件。JIT、OS 缓存和磁盘负载导致波动；三轮只报告中位数和范围，不用三个样本包装 P95/SLA。固定回放采用交错顺序；完整目录验证先 A 后 B，各自先预热一次。没有压正式 HTTP 服务、写正式库、重启正式服务或清缓存。

正常覆盖以现有契约的文件大小/修改时间等元数据识别；**若上游覆盖后刻意保留完全相同的大小和修改时间，原实现和本次实现都无法识别内容变化**。未增加全内容校验。异常时保持保守清理，回退路径性能也可能回到逐文件水平。

本轮针对普通 WebP/NC 的无变化索引更新；RePPIC 三文件批次保持原事务路径，没有对它声称同等性能收益。未验证几十万/百万文件规模，不承诺扩大数据后仍保持相同倍数。

## 简历与 STAR

> 针对气象文件历史积累造成的重复索引更新开销，通过每 200 条批量读取索引与关联、差异更新及批量已见标记，在隔离 MariaDB 上将 9,242 个真实文件的无变化全目录重扫中位耗时从 50.56 秒降至 1.12 秒（各三轮），SQL 执行次数减少 99.47%，并验证历史回补、覆盖更新、缺失文件及完整批次处理。

面试时主动说明测试环境、数据规模和三轮范围；不能把 1.12 秒说成线上 SLA，也不能写成检索延迟降低。

S：气象 WebP 定期新增、历史 NC 长期保留，旧扫描每个文件都查资产、查产品关联、提交更新；无变化扫描也反复访问数据库。

T：先确认瓶颈，再减少重复索引更新开销，同时保留历史回补、覆盖检测、缺失清理、完整批次和异常保护。

A：用生产原实现建立隔离库基线；拆分目录与存储耗时。按 200 条分块预读索引和关联，内存比对，无变化记录批量标记；新增/变化复用原规则。分块事务失败整体回滚再逐文件处理，RePPIC 原子发布保持不变。

R：引用上方三轮中位数、SQL/提交次数和真实数据量；解释固定回放与完整扫描的区别，提供状态指纹和 14 个真实数据库正确性用例。明确这是**索引更新优化**，不是检索性能优化，也不是 TB 内容解析。
